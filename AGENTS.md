# AGENTS.md

Guide for coding agents working on **Last Stand**, a browser 3D wave-survival ARPG (Three.js + TypeScript + Vite). `README.md` is the player/contributor overview; this file covers the things that aren't obvious from the code.

## Commands

```bash
npm install
npm run dev          # Vite dev server, http://localhost:5173
npm run typecheck    # tsc --noEmit (strict)
npm run build        # typecheck + production build into dist/
npm run check:pages  # after build: every asset path must work under the Pages base path
```

There is no test suite. Verify changes with `npm run build` and by playing the dev build in a browser. A hero's face is measured against a reference picture with `npm run facelab` (`tools/facelab/README.md`; once: `npm run facelab -- --setup`).

## Workflow

- **Every change goes through a PR** from a branch off `main`; never push to `main` directly. Each PR gets a live preview at `https://victorzakharov.github.io/last-stand/pr-preview/pr-N/` (sticky PR comment), forks included: `pr-preview-build.yml` builds the PR with a read-only token, then `pr-preview.yml` (a `workflow_run`, always the copy on `main`) checks the artifact's PR number against the API and publishes it. Never run PR code in `pr-preview.yml`. Fork runs need the maintainer's approval on every push (repo setting "all external contributors"), so nothing from a fork publishes unseen. Merging to `main` deploys production (`deploy-pages.yml`).
- **`main` is protected:** PRs only, merged with a merge commit (squash and rebase merges are disabled), and the branch must be up to date. **PR branches must be linear:** `git rebase origin/main` to update, never merge `main` into a branch. The `branch-policy.yml` check fails any PR containing merge commits. Merged branches are deleted automatically.
- Pages is served from an aggregated `gh-pages` branch: production at the root, open PR previews under `pr-preview/`. Don't switch Pages to "GitHub Actions only" and don't delete that branch.
- Keep PRs focused on one feature.
- **Prompt starts with `new issue:`** (fork workflow): run `scripts/issue.sh "title" "description"` with a title and description you write from the prompt, then do the work on the branch it creates. When done, run `scripts/commit.sh "PR title" "PR description"` instead of committing yourself, and reply with the PR link.

## Product rules

- **Core loop:** after *every* wave the player chooses Bank (keep all loot, leave) or Continue (harder wave, better loot). Dying loses all unbanked loot. Loot is **hidden until banked**: nothing drops on the floor, items go straight into the run's bag (`gainLoot` in `game/run.ts`), and the HUD shows only counts per rarity. The bank summary reveals the items one by one. Don't show what an unbanked item is (name, base, stats) anywhere. Don't change this without being asked.
- **The lobby floor** (`game/groundItems.ts`): gear given up in the lobby (dragged onto the game field, Shift-click, the touch sheet's Drop) is thrown on the floor, not deleted. Clicking its name (on touch: a tap shows the card, a second tap takes it) puts it back in the stash, if the class can use its base and the stash has room. In co-op every game shows every drop and the host decides who got one first (`gdrop` / `gtake` / `gtaken` in `net/session.ts`). Whatever is left on the floor is lost when a run starts, and a guest leaving the room leaves it to the host.
- **Everything is procedural.** No downloaded models, textures or audio: geometry, canvas textures, rigs/animation, VFX and WebAudio sfx are generated at runtime. Don't add binary assets (screenshots in `docs/` are the exception).
- **Originality:** this is open source. Skill, item, enemy and class names must be original. No Grim Dawn (or other game) names, trademarks or assets.
- The game is class-agnostic by name ("Last Stand"). More classes are planned, so keep class-specific code in class data, models and skills, not in the shared systems.
- **The UI must fit any screen size, desktop and mobile.** Anything that overflows or overlaps at some viewport size is a bug.
  - Scale: `--ui` for the lobby and modals, `--hud` for the in-run HUD, `--touch` for the touch controls (all set in `src/ui/scale.ts`).
  - Layouts: on desktop the lobby is a CSS grid `[left | center loadout | right]` with the panels against the screen's edges; each folds away to its edge on its own, leaving a labelled tab (`FOLDS` in `ui/menus.ts`, kept in `localStorage`). A fold tab stands outside its panel's frame, so a panel that scrolls does it inside (the left one's `.ml-body`), never on the panel itself. Short screens (phones held sideways, height ≤ 520) and upright tablets show one panel at a time, picked from `#lobby-rail`, and the camera view shifts so the character stays beside the panel (`lobbyViewShift`); they never fold a panel. Phones held upright get a "turn your device" overlay.
  - Check desktop at 1024×700 and 1920×1080, a phone at 844×390 and a tablet at 1180×820 and 820×1180 (Playwright with `isMobile` + `hasTouch`).
- **Installable, offline (PWA):** `public/manifest.webmanifest` plus a build plugin (`scripts/pwa.ts`, production builds only).
  - Install: Chrome and Edge fire `beforeinstallprompt`, and the lobby's Install link opens it. Safari (iOS) and Firefox never fire it, so on phones and tablets the link is always shown (unless already running installed) and opens `#install`, the add-to-home-screen steps for that platform.
  - The plugin renders the PNG app icons from `public/icon.svg` at build time (no binary assets in the repo) and writes `dist/sw.js`, which precaches every built file.
  - The worker's cache name is a hash of the build, so each deploy installs its own cache (fetched past the HTTP cache: Pages sends `max-age=600`) and takes over at once. It keeps the previous build's cache, so a page still running the old build can load its remaining chunks.
  - **A plain reload must show a new deploy:** the page is served network-first (the cached copy when offline or after 4s), the built files cache-first. `src/ui/pwa.ts` registers the worker (`updateViaCache: 'none'`, checking again when the tab comes back into view), shows the Install link and offers a reload in the lobby when a new build took over an open page (it asks the worker which cache it serves). Production's scope contains the PR previews, so the worker skips `pr-preview/` paths (each preview registers its own).
  - The pause menu shows the build (`__BUILD__` from `vite.config.ts`: commit, a preview's PR number, the build time in local time).
  - Test offline behaviour with `npm run build` + `vite preview`: the dev server has no worker.
- **Touch** (`src/ui/touch.ts`): touch mode (`body.touch`, `input.touchMode`) follows the last pointer used, and the browser's emulated mouse events are ignored in it.
  - Controls: a move stick on the left half and the skill buttons on the right. Tap casts at the nearest foe; drag aims by hand and casts on release. The basic attack and channels act while held.
  - Everything hover-only needs a touch path. Tooltips open on tap (`bindTooltip`); items open an action sheet (`openItemSheet`); skills are bound by tapping a key and then the skill. Drag and drop and Shift are desktop extras.

## Architecture

| Path | Contents |
| --- | --- |
| `src/types.ts` | Shared types: data definitions (`SkillDef`, `ClassDef`, `EnemyDef`, `Item`...) and runtime (`Model`, `Effect`...) |
| `src/data/` | Pure tuning data typed against `types.ts`: classes & skills, enemies, biomes (roster, boss per biome), items/affixes, waves, `balance.ts` (camera, arena, run constants) |
| `src/combat/skills/` | Skill behaviours, registered in `index.ts` (`SKILL_IMPLS`) and referenced from class data by `impl` name. Instant: `cast()`. Channel: `start/tick/stop` with a typed state object. Use `Needs<'field'>` to require optional `SkillDef` tuning fields |
| `src/entities/models/` | Procedural models, registered in `index.ts` (`MODELS`); `rig.ts` = shared humanoid skeleton + pose helpers |
| `src/game/run.ts` | Wave flow, scoring, loot rolls, bank / continue |
| `src/world/` | `arena.ts` builds every biome at boot and switches between them; one builder per biome (`crypt.ts`, `forest.ts`), shared pieces in `props.ts` (the night and day skies too), the Thornwood's leaf-card foliage in `foliage.ts` |
| `src/loot/` | Item generation (base names and excluded stats per class), save slots (`saveSlots.ts`), persistent profiles, one per class and save slot (`localStorage` `last-stand.profile.<classId>.v1`; the pre-class `last-stand.profile.v1` migrates to slot 1's mage), the lobby's class (cookie `last-stand-class`), skill loadout (cookie `last-stand-loadout-<classId>`; a class with gear-driven skills keeps one per weapon style, `last-stand-loadout-<classId>-<style>`). Slots 2 and 3 put `s2` / `s3` after the `last-stand` prefix of each name |
| `src/fx/` | CPU particle pools, a fixed pool of 8 point lights (`lights.ts`), transient effects (`effects.ts`) |
| `src/core/` | Renderer + post chain, input, audio, procedural textures & materials, game-time scheduler (`timers.ts`) |
| `src/net/` | Co-op: who simulates what (`role.ts`), the links (`transport.ts`: Trystero over Nostr relays, or `?net=local`), rooms, lobby and each player's own state (`session.ts`), the host's reports of the fight (`sync.ts`) |
| `src/ui/` | DOM HUD, lobby/menus, tooltips, loadout editor, item icons (inline SVG), attributes; the stylesheets (`styles/`, SCSS) |
| `src/vendor/cape/` | Vendored cape-physics PBD solver + shims. Keep the solver files unmodified (see its README); adapt in `entities/models/cape.ts` and the shims |
| `src/state.ts` / `src/events.ts` | Typed global state `G` and a typed event bus |

**Adding a class:** a data file in `src/data/classes/` registered in its `index.ts`, a model in `entities/models/`, and skills in `combat/skills/`. Class data also sets the lobby accent, the loadout panel title, the cast-point light and item base names; give new bases an icon in `ui/itemIcons.ts` and the class an equipment silhouette (`#equip .doll[data-class]` in `index.html`). Classes share no progress: each has its own profile. Switching class in the lobby rebuilds the `Player`, and `game/warmup.ts` builds every other class model at boot so that compiles nothing.

**Adding a biome:** an entry in `data/biomes.ts` (enemy pool, boss, minimap), a builder in `world/` registered in `arena.ts`, and its enemies in `data/enemies.ts` with models in `entities/models/`.

## Gotchas

- **NaN means black lines or boxes on screen.** Bloom smears NaN/Inf pixels across the frame. Known causes: GLSL `smoothstep(a, b, x)` with `a >= b` (it's undefined, so write `1.0 - smoothstep(b, a, x)`), and `atan(0, 0)`. `renderer.ts` has a sanitize pass before bloom as a safety net; still fix the source.
- **Bright effects:** light adds up, so the final grade (`core/renderer.ts`) compresses it the way the eye does, and effects and their lights stay at full strength: don't dim single effects to fix a bright scene.
  - **Adaptation:** after bloom, the average light over a 16x9 and a 4x3 grid of the frame (`AreaPass`) is held under per-view targets (`ADAPT`, just above each view's ordinary scenes, which it leaves untouched) by compressing only the light above `ADAPT_BASE`, on a power curve. Never scale a whole pixel by its area's brightness (the dim ground round an effect darkens into a shadow around it), and don't adapt before bloom (effects drop under bloom's threshold and turn into flat discs with no glow). Above `HI_KNEE` the brightest channel eases towards `HI_CAP`, and in a large glare tone mapping keeps a bright pixel's colour (`HUE_*`, `GLARE_*`), so a big bright area stays green or blue instead of turning white.
  - **Distance:** effect materials dim with their distance from the camera (`nearGlow` in `core/materials.ts`: full strength from the top-down camera's distance, down to a quarter up close). `additive()`, the glow particles, projectile cores (a hostile bolt's is an orb of added light, with a pooled light when one is free; the spore throwers' are `fx/sporeOrb.ts`, the Rift Witch's and the Colossus's `fx/riftBolts.ts`: blended orbs, with added-light tails and halos), entity glows (`kit.glow`, the staff orb included; a hero's gear glows opt out) and the hit flash on bodies have it; wrap a new effect material in `nearGlow()`. The world's own glows don't.
  - **First person:** particles fade within 3.5m of the camera, a bolt flying at the camera shrinks away over its last metres (never pops out: nothing near the camera may switch off at once), and a cast leaves from `Player.castPoint` / `palmPoint`, which in first person are the weapon and hand in view. Keep lights off the camera: above the head, not at 2m. An effect round the body (a heal, a war cry) is seen from inside it: `Player.eyes` tells a skill it is, so it can put its particles where they're seen (a wider ring) and its light ahead of the view (`Player.lightAhead`; straight above, the weapons' steel mirrors it back into the view).
  - Nothing large may flash or pulse faster than about 1.5 times a second: 3+ flashes a second is a photosensitivity hazard. A hit's flash on a body is full at most every 0.7s (`hitFlash` in `util.ts`).
- **Creature geometry** (`entities/models/shapes.ts`): the enemies sculpt their bodies from tapered tubes, lathed limbs, noise-displaced shapes, leaves, fern fronds, branching boughs and winding strands on the rig's joints (`stripRig` removes the stand-in capsules), and `Sculpt` merges each joint's pieces per material into one mesh. `new Sculpt(kind)` caches the merged geometry per kind: later builds of the kind replay it (the builders return at once), so spawning stays cheap. That needs a deterministic build (seeded `mulberry`, never `Math.random`), and the shared geometry is never disposed (`userData.shared`, skipped in `Enemy.dispose`). The mage's bell sleeves are cloth (`models/sleeve.ts`: verlet particles on a tube, pinned by their top ring and hanging by gravity, hoop constraints keeping the section round, collided with the forearm and the body (`bodies`: torso, hips, skirt); don't add a spring back to the animated shape, it makes them rubbery; each particle kept within the radius it was cut to round the forearm (so the arm never leaves the sleeve), a tether to the top ring and carrying the cloth along with part of the animation's motion stop it streaming off the arm at a run, and each row's slide up the forearm is capped (`SLIP`) so a turn or a lean never bares the hand; stepped in `animate` after the pose; `?cloth=0` holds them at the animated shape), and the warrior's fur sways (`models/furSway.ts`: a spring on each fur mesh in the vertex shader, weighted by the uv's v along the tuft; `?fur=0`). A piece that crosses a joint (a sleeve over the elbow, the neck into the head) goes through `Sculpt.skin` / `skinPair` instead of `add`: analytic skin weights from its position along the bone, one `SkinnedMesh` per joint for a hero (the first-person view hides by joint) and one per material on the root for a creature. Skinned meshes must keep their own copy of the material and their own `customDepthMaterial` (both done in `build()`), or a crowd pays for three rebuilding program parameters at every rigid/skinned switch; `Player.dispose` and `Enemy.dispose` free the skeleton and that copy. `?skin=0` puts them back on one joint. Pieces under 7 cm cast no shadow, and neither does a material passed to `Sculpt.glow` (glows, and leaves). For skin and cloth use `kit.rim` (a rim of light at glancing angles) rather than a physical material's sheen, which costs far more per pixel.
- **Hero models** (`models/mage.ts`, `models/warrior.ts`) strip the rig's stand-in capsules and dress it from shared parts:
  - **Proportions are a real man's** (ANSUR II, the US Army's survey): 7.5 heads tall, shoulders, chest and hips at real widths plus the clothing or armour on them. Size new gear to that frame; exaggerated shoulders make the head look small.
  - `models/face.ts`: each hero's head as a signed distance field in millimetres, sculpted from average measurements, with a face shape (`FACES`) and colouring (`LOOKS`) per hero.
    - It's meshed by casting rays from inside the skull on a grid densest over the face (`headGrid`).
    - It's painted on the same grid in the loading workers (the `face` recipe in `core/pbr.ts`), so the texture fits a grid of any detail.
    - The rays start lower for the jaw and higher for the brow, so none skims along the skin. A shape that leaves a hollow inside the head, or an overhang seen from the rays' start, shows as streaks.
  - `models/head.ts` builds the head: skin, eyes under lids, ears, hair cards (alpha-tested strands), and the neck. Hair comes in styles (`buildHead`'s `hair`): `swept` back to the nape (the mage) or `loose`, thick and wavy to the jaw (the warrior: the front swept up off the forehead, falling over the ears, the ends flicking out), each lock shaded on its own (vertex colours: darker at the root and in its waves' hollows). Locks start flush with the scalp behind the hairline (a lock's square root end shows as a block), and the cap over the scalp rises gradually from behind it, across a hairline running steeply down at the temples too (a step within a grid cell shows as a stair). Beyond the shape (`FACES`), a face is tuned by optional fields: `bridge`, `browDrop`, `hollow`, `lowerW`, `beardLine`, `beardUnder`, and in its look `hairDrop`, `brows`, `browArch`, `pores`, `stubble` (a short-cropped beard), `contour` (shading painted where light falls less), `lipTint`. Tune a face against its reference with the face harness (`npm run facelab -- --ref <picture>`, `tools/facelab/README.md`): a studio render square to the face, landmarks found the same way on both pictures and aligned by the eye corners, zoomed crops of each feature side by side and overlaid, and a report of proportions, the face's outline, the brows and the hair's outline; not by screenshots judged by eye in a biome's light. `Head.hair` lists the hair's meshes, which a model hides under a helmet: a hero wears its helmet or hat only with a head item equipped (`Gear.helm`), bareheaded otherwise.
    - `toGroup` places anything by the head's anatomy (mm).
    - `surface` gives the skin in any direction, and the helmet and hat are shaped with it.
  - `models/hands.ts`: three-jointed fingers. A hand holding something stays on its wrist: it turns so the handle runs across the palm (its length along the forearm, the wrist bending only as the handle needs), and the weapon is seated in that palm (`seat`, a grip joint moved to where the fist closes, whenever its turn changes). `hold()` then closes each finger snugly round the handle (each segment bends just until its end touches it, whatever its radius), the thumb over them from the other side. A hand reaching a grip it doesn't carry (a two-hander's lower grip) puts its wrist where its fist lands on it (`fistReach`) and reaches that by arm IK.
  - `models/armor.ts`: plates with thickness (`plate()` faces them away from their joint), straps, fur, and `Skirt`, a continuous skirt that swings with the legs. Its `taperTube` / `twist` face outwards, unlike the creature versions in `shapes.ts`, which wind inwards.
  - `core/engraving.ts`: the engraved steel atlas (breastplate, medallions, knee cops) and embroidered panels; the new tiling maps (leather, mail, cloth, steel, fur) are PBR recipes.
  - `rig.groundFeet` is leg IK run after the pose: a crouch bends the knees instead of sinking the feet, and a planted foot lies flat.
- **Leg IK and head look-at** (`models/ik.ts`; `?ik=0` turns both off and restores the walk cycle's own legs and gait for A/B): `LegIK` runs at the end of a model's `animate` (heroes and every walking enemy, not the floating witch) and takes the legs over. A planted foot is held at a world spot while the body moves over it; a swinging foot arcs to where it will land (predicted from the body's speed), timed by the walk cycle's phase, which `gaitRate` keeps in step with the speed and the leg length (`Player.animateBody`, `Enemy.gait`: a step per half cycle, so the stride matches the ground covered); a standing character re-steps when its feet fall too far from under it; the pelvis (`body.position.y`) drops when a foot would be out of reach; a foot lies level on `groundHeight` (dais steps); each leg is two-bone IK (`reachArm` with `hinge = -1`), blended over the pose by a smoothed weight. The gait follows a real runner's (`stepLength`: cadence from the speed, a step at most 1.65 leg lengths; duty falling with speed to about a third, so a run has about a third of its time in the air): no step moves a foot's target faster than a running swing (`FOOT_V`, `FOOT_VK`): when the plan jumps (the phase or the way the body goes turning round as an attack turns the body onto its aim while it strafes or backs up) the foot catches up over a few frames instead of teleporting, a swing whose window was already under way when the foot could leave runs its whole arc in the time left (`tw0`), and a landing is never predicted more than 0.6s ahead. Don't fix such jumps by turning swings into timed steps: the feet shuffle. Check with per-frame ankle jumps in a real run (attacking while strafing) and the gait's state shares against main's. Keep the swing's landing offset (`half`, capped at 0.4 of the leg, `SLIP` is 0: a planted foot never creeps) and the duty within the legs' reach: at speed the contact shortens so the body passes over at most `STANCE` leg lengths of ground, as a runner's does. A planted foot rolls instead of sliding (`roll`: the heel stays put as it lands, the toes as the heel peels up, the ankle moving only round them), turns about the ball of the foot (`BALL`), and when the body goes out of its reach it keeps its spot and steps at once (`over`), never dragged. A swing starts and lands where the ankle actually is, carrying its pitch on, its first frame already under way, and a foot in the air eases into the leg's full stretch rather than meeting it. Measure leg quality with the deterministic probe (`legdet`: a fixed 1/60s clock and scripted input; contact-point slide, ankle and knee acceleration, crossed legs) after restarting Vite, against main and the duty within the legs' reach, or the pelvis dips at each step. **A swing is drawn in the hip's frame, not the world's** (a cubic from where the foot left to `half` ahead, its tangents the stance's backward stroke: `STROKE_OUT` / `STROKE_IN`): a foot eased along in the world trails behind the hip, then rushes ahead of it and dangles under a squatting pelvis. Judge a gait by its joint-angle curves over the cycle against a runner's (hip and knee flexion against the phase from touchdown, from joint recordings), not by the pelvis height: an upright torso over legs that are flexed all the way round reads as a squat at a pelvis height that looks fine. A body that travels sideways to the way it faces (a hero casting or attacking, where the body faces the aim) turns its pelvis and legs towards the way it goes and turns its chest back (`twist`, `TWIST`), or its feet cross. Moving in any direction while attacking, the legs keep one coherent left, right rhythm (count it: the same foot leaving twice running is a break), crossing a little as a person's do: moving, no extra corrective step is ever taken (it would be a double step); a planted foot the body is about to leave out of reach takes its own stride early instead, stretched to land on time (`EARLY`), even with the other foot in the air; a stride's progress only goes on, by however far the cycle moves either way (a reversal turns the phase back: following it the foot swung back the way it came), and when the way the body goes turns round under it, the same stride is aimed afresh from where the foot is; a planted foot out of reach rises onto its toes (`peel`) rather than sliding; only a body wheeling round on its feet (`yawRate`, smoothed so an attack's snap onto its aim doesn't count) steps out of turn. Between one attack and the next the body stays on its aim (`AIM_HOLD` in `player.ts`): wheeling round to the way it goes and back at every blow made the legs dance. The pelvis turns at most `TWIST` (0.8 rad), and the legs walk along its line, forwards or backwards: going back and to the side it turns the other way and backpedals (never steps sideways backwards across itself), each way costed by how far the legs go off its line plus how far it turns (`TURN_COST`, `HYST`). The legs step up to `SLACK` off that line first (a diagonal is walked with the hips half turned, so forwards to backwards along it turns them less), and the hips turn no faster than `TWIST_RATE`. A stride is drawn along its own direction, turning towards the way the body goes rather than snapping to it (the foot whipped across), and a stride re-aimed late keeps a third of a swing's time at least. Check with the probe's leg-to-pelvis angle and pelvis turn rate (`d:w/s+atk`, `sd+atk`). A reversal (left, right, left again while attacking) doesn't swing the pelvis round through the aim: it keeps its line and the legs go backwards along it (`backing`), turning round only after `BACK_HOLD` of going the new way, and it holds its turn while the smoothed velocity collapses mid-reversal. No foot lands or swings across the pelvis's middle (`GAP`), and a planted foot a turn leaves across it re-steps (`CROSS`). Test with the zigzag probe (attacking while switching left/right, forward/back and diagonals every 0.25-0.7s; count crossed-leg frames in the gait's pelvis frame, ankle jumps, both feet up) against main. The hero models bracket `legs.update` with `captureArms()` / `holdArms()`: each wrist keeps its hand's world turn through the lean and the pelvis's dip, so a weapon or shield keeps its angle (the hands' positions follow the body: pinning them too folded the elbows into the chest); a pose that needs a hand turned does it before `captureArms`. The body moves with it (`walkCycle`): at a run it is highest in flight and lowest as a foot takes the weight (a walk is the other way round), and it shifts sideways over the foot it stands on. Measure a change against a runner's numbers (cadence, contact and flight time, knee and hip angles, lean, bounce) with joint recordings drawn as stick figures, not by the pelvis's height alone. Keep the matrix work to the hip chain (a crowd pays for it every frame: updating the whole skeleton here cost 8x more). It does nothing while the body is off the ground (an enemy rising at spawn) or dying, and restarts under the hips after a teleport (`reset()`). Everything is local and visual: a co-op copy computes it from the motion it replays, so there is no protocol change. **Where a standing body puts its feet is the pose's to say** (`legs.stance(i, x, z, turn)`, in the root's own frame; the heroes' `*_FEET`): a foot further than a few cm from its spot steps there, one at a time, its knee bending over the way it points, so an idle's stance (side-on, the rear foot turned out) and an attack's step in are real steps; moving, the gait ignores it. The pose then moves the pelvis freely (`body.position`, the hips' turn and roll: a weight shift, a lunge, a crouch) and the planted feet hold. A pose that moves the body faster than feet can step (a dash's lunge or charge) or spins faster than they could follow (Steel Tempest) owns the legs: it passes a lower `weight` to `legs.update` (the warrior's `legOwn`), the lean, twist and pelvis fade with it, and the feet restart where the pose has them when it gives them back; one leg alone goes through `legW` (`ownL` / `ownR`), the other staying planted. Enemies skip the leg IK out of the view and, on Low, beyond `ikRange` from the player (`LegIK.active`); film a new skill side on with and without `?ik=0`. `LookAt` turns the chest, neck and head onto the nearest foe (heroes) or the target (enemies), from the body's position and facing alone; not through the eyes (the camera rides the head). The heroes run it inside `animate` before the leg IK and the cloth (`AnimState.look`), since the chest's share moves the arms the sleeves and cape follow; enemies after `animate`.
  - **Hero moves are full-body and keyed** (`models/motion.ts`): an attack is written as keyframed curves over its progress (`curve(keys, k)`, a monotone cubic: an overshoot or a hold is a key of its own), one per channel, and moves the whole body, not just the arms: a wind-up (the weight back onto the rear foot, the hips and chest coiling away), the blow led from the ground up (the hips turn first, the spine and chest after, the arm and wrist last: the same curve read a few hundredths earlier for each joint down the chain), the weight forward and down into it, a follow-through past the hit, the other arm countering and the head kept on the foe. Keep a move's hit where the skill fires (the swing's tip crosses the arc from 0.55 to 0.85 of the cast, in step with the trail). `PoseFade` crossfades every cut between poses (an action starting, restarting or ending: from the pose shown just before, over a fifth of a second or so, slower out of a blow that should be seen to recover), so a move may end on its follow-through and let the fade bring it home. A short cast's end (a throw, a blow, a roar) is held a moment after the cast is over and then eased out (`TAIL` / `TAIL_OUT` in each hero model; moving off or another action cuts it), so it is seen without slowing the gameplay. The healing draught is drunk (`models/flask.ts`: the free hand takes a flask from the belt and arm IK lifts it to a mouth point on the head, from where each model holds it, `DrinkHold`; the warrior's shield hangs from that forearm before the chest meanwhile, a second weapon is worn on the belt (`DRINK_SHEATHED`: in a leather frog at the left hip, a sword by its guard with the blade raked back along the thigh, an axe or mace head up; `Weapon.hang`) and drawn again, a two-hander lets go of its lower grip, and the mage's sleeve is pushed back up the arm). Its beats are smooth keyed curves (`HIP`, `LIFT`, `TIP`, `OUT`), the flask aimed from the planned wrist, not the moving one (check with a per-frame speed and turn-rate probe). It is a `freeMove` cast: no other skill while it lasts, but full speed and facing the way the hero goes. A dash may pace itself (`DashOpts.pace`: Bull Rush braces, accelerates and skids, covering the same distance). The idles are alive: a stance with the weight shifting from foot to foot (the pelvis swaying over them, the hips tipping, the shoulders answering), breathing in the shoulders, the weapons at the ready, a blade held edge on to the foe in a neutral grip, thumb up and palm in, the wrist nearly straight (`REST_ARM`, `REST_TWO`: the forearm angled down so the blade rises from the fist; measure the wrist's bend from the forearm in the hand's frame) (`MOUNT`: in third person every weapon sits in its fist as a real one does, its flats along the palm and its edge or bit out over the knuckles; a move that must lead with the edge rolls the forearm, `edgeOn` about a blade along the arm: palm up on a forehand swing, down on a backhand, `SW_ROLL`, `FANG_ROLL`; never turn a blade held across the forearm that way, it bends the wrist instead. Check with a probe of the flat's normal against the tip's motion and the palm's against the flat). First person keeps its own hand-placed poses (`FP_*`); the full-body versions are third person only. Check a move with a frame-exact film (the game paused, `animate` stepped through the action by hand) from the side and the front.
  - Hero geometry detail follows the quality preset (`heroDetail`), taken when a hero is built.
- **Point lights:** use the pooled slots in `fx/lights.ts`. Never add ad-hoc `PointLight`s, because changing the light count recompiles every shader.
- **Shaders compile at load, never mid-game.** `core/shaders.ts` pins every compiled program (three.js would delete it when its last material is disposed) and `game/warmup.ts` renders one of every enemy, effect, drop and skill visual at boot. A skill with its own materials must return sample meshes from its `warm()` hook. The perf overlay (pause menu) shows `Shaders N (+M)`: M must stay 0 during play, and the copied report says what compiled late.
- **Keep loading in short chunks:** a window moved to another monitor shows black until the main thread can paint it, so boot work yields between steps (biomes, enemy warm-up) and the procedural PBR maps are made in workers (`core/pbr.ts` recipes, `PRELOAD` list, `core/pbr.worker.ts`; a map missing from `PRELOAD` is still made on the main thread on first use, just slower). Measure with a `longtask` PerformanceObserver: nothing much over ~0.5s.
- **Loading screen:** `#loading` (markup, SVG logo and styles) is inline in `index.html` so it paints before the bundle. The game renders behind it but only advances once it fades (`revealed` in `main.ts`), so the lobby intro is seen. Tips are in `data/tips.ts`. Its exit (`ui/logoWind.ts`) snapshots the SVG letters (the font is inlined, since an SVG image can't load web fonts) onto the device pixel grid, turns every pixel into a WebGL point, blows them away and gathers them into the lobby logo (`#menu .logo-art`, kept hidden until then). The motion is closed-form in the vertex shader. No copy of a logo is ever shown at rest, so the two never visibly swap: a point is drawn only once the wind lifts it (the real letters are clipped away just behind the front), and landing points take the colours of a snapshot of the lobby logo, which is then uncovered left to right under them. It scales to the device: touch and low-end machines get a ~120k point budget (a coarser snapshot and a 2× canvas) instead of 1.5M. A watchdog cuts it short when the first frames run under ~20 fps, and remembers that (`last-stand.logo-wind-off`). It falls back to a plain fade with reduced motion, Low graphics quality, or after the watchdog tripped.
- **Canvas size:** `fitViewport` in `core/renderer.ts` fits the canvas, render targets and camera on resize *and* every frame, and ignores zero sizes. Moving the window between monitors can report a zero height mid-move (zero-sized render targets: a black screen until the next resize) or change the pixel ratio with no resize event. Read the window size through it, not `innerWidth`/`innerHeight` directly, in anything that feeds the camera.
- **Quality presets** (`data/quality.ts`, pause menu, Auto by default) change pixel ratio, MSAA, shadow map size and which small character parts cast shadows, all live and without shader changes. Keep new settings in that category, or they cause compile hitches when switched.
- **Static shadow casters are baked:** `bakeStaticShadows()` in `world/props.ts` merges every non-instanced caster of a biome into one shadow-only mesh. Arena props must not move after the arena is built. The bake keeps positions only, so an alpha-tested mesh (leaf cards) must not cast from a single mesh: it would cast solid quads. Instanced ones cast properly (three's shadow pass honours `alphaTest`).
- **Biomes:** every biome is built at boot into its own group, and switching only toggles visibility and sets the shared lights, fog and environment (`BiomeLook`), so it's instant. Each biome must add exactly **6 point lights** (a different count recompiles every lit shader; dev builds log an error), keep the central dais footprint (`world/ground.ts` is shared with the cape worker) and the four gates at the same angles. Boot warms up the lobby in every biome. The lobby choice is a cookie (`last-stand-biome`); Random rolls a biome when a run starts.
- **Cape:** the cloth steps in a web worker (the solver's own `WebGlCapeWorkerPool`); the main thread applies the latest result, shifted onto the current neckline to hide the round trip. Without workers it steps on the main thread within a per-frame budget, so a slow frame can't snowball into more catch-up steps. `SkeletonCape.update` must call `sim.syncGeometry()` after new particle positions arrive, or the cape freezes at spawn. The floor shim imports `world/ground.ts` directly (a worker shares no state with the page). Colliders are capsules built from rig joints in each class model (`models/mage.ts`, `models/warrior.ts`).
- **Lobby sandbox:** in the lobby `player.sandbox = true` (free casting, no costs or cooldowns). `start()` clears it.
- **Save slots** (`loot/saveSlots.ts`; the screen is `ui/saves.ts`, from the lobby's "Save slot N"):
  - Everything saved for the heroes goes through `saveKey`: profiles, loadouts, stash filters and the lobby's class. A slot's delete (`erase` in `ui/saves.ts`) must remove each of them, so new per-hero storage needs both. Preferences (quality, battleground, perf overlay) are shared by all slots.
  - Slot 1 keeps the keys from before there were slots. PR previews and a cached production build share this origin's storage and only know those keys, so don't move slot 1.
  - Switching slot (`switchSaveSlot` in `main.ts`) rebuilds the hero in place, like a class switch, and in co-op sends the new look. While the screen is open the hero stands idle and the screen takes Esc.
- **Gear-driven skills and block:** `Player.gear` comes from the equipped items: weapon base, two-handed (`ClassDef.twoHanded`), shield (an off-hand with Block Amount), and a weapon in the off-hand (`ClassDef.dualWield`: a one-hander fits the off-hand slot, and its implicit counts at `OFFHAND_WEAPON`). Each weapon style (shield, two-handed, dual, one-handed) has its own loadout (`loot/loadout.ts` `weaponStyle`); changing style loads that style's, and a style not set up yet starts from the class defaults fitted to the gear. With two weapons the model's swings alternate hands, and `tip` moves to the swinging weapon. A two-hander is held in both hands, the left one following its lower grip by arm IK (`fistReach` in `models/hands.ts`); a pose that takes that grip out of the left arm's reach (Steel Tempest, the war cry's flung arms) lets go with it, the arm easing back to the pose's own, rather than leaving the hand floating off the wrist. `Model.setGear` shows it, and `profile.equipFromStash` never lets a two-hander and an off-hand be equipped together. A skill with `needs: 'shield'` (or `'twoHanded'`) gives way to its `fallback` for the gear held (`Player.skillAt`), and the lobby dims it in the skill book while the gear doesn't allow it (`Player.usable`). Blocking is in `Player.tryBlock`: a per-hit chance with a recovery (`BLOCK` in `data/balance.ts`), or every frontal hit while a skill with `block` is channelled, until a hit bigger than that breaks the guard and staggers the player (`guardBroken`, `staggered`: move only). Melee skills draw their trail through the weapon tip (`skills/cleave.ts` `swingArc`), so keep the model's swing timing in step with it.
- **Breakable props** (`world/destructible.ts`): everything standing in the arena has hit points and breaks under focused fire (the walls and the boundary don't): player and hostile bolts (`Projectile` world collision), the Void Lance beam, melee swings (`sweep`, whether or not they found a foe) and every area skill (`hurtPropsIn(player, x, z, radius, amount)`: Starfall, Glacial Nova, Maelstrom, Tempest, Crescent, Iron Bellow, Bull Rush; a new area skill calls it next to its `hitEnemy` loop). `PROP_DAMAGE` sets the weights, each prop its own `hp`. A biome builder registers one with `PropSet.add(from, hp, debrisColour, look)` *after* pushing its obstacle circles (`from` is the first index; a log is several circles, one prop), `look` being `instanceLook(mesh, i)` (an instance shrunk away), `meshLook(...meshes)` (hidden) or, for a built assembly, `groupLook(group, updaters, from)`: build it into a `THREE.Group` and it hides its meshes, stops the `updaters` it added, and only darkens its point lights, never removes them (the light count must stay 6). Anything that can go is kept out of `bakeStaticShadows` (`userData.noBake`), so a new prop's meshes must be registered through one of these. Breaking takes the circles out of `G.arena.obstacles` and bumps `state.rev`, which rebuilds the navigation grid. Damage only counts where `simulates()`; the host reports each prop's health (`prop` event) and a guest applies it (`setPropLife`), so bump `PROTOCOL` if that changes. Broken props stay broken from wave to wave and come back when the next run starts or in the lobby (`G.arena.restoreProps()`). A prop breaks into pieces shaped like what it was (`fx/rubble.ts` throws them, `fx/rubbleGeo.ts` is their geometry and painted textures; `PropSet.add`'s last argument is its `RubbleKind`, `stone` by default: `stone` faceted shards with weathered outsides and fresh fracture faces, `wood` tapered splinters, flakes, bark strips and torn stubs on a grain atlas, `shroom` glowing dome fragments of cap (skin above, gills below) and torn fibrous stem pieces on a mushroom atlas, `ember` charred sticks and glowing coals; a new kind is a recipe of those shapes there). The pieces tumble, bounce, topple onto their broad face (a dome fragment lies convex side up; nothing rests on its end), stay about 6-9s and shrink away. Each kind of piece casts a shadow only where the quality preset's `minCasterRadius` allows (`setRubbleShadows`; every populated pool is a draw call in each shadow pass). A glow is only an emissive colour or map on a standard material, and every program is warmed in `warmup.ts`. A damaged prop shows a `.pbar` (a notched stone gauge, not the foes' red bar) for 5s after the last blow, then fades; it sits no higher than 2.2m and is clamped to the screen (`addAnchored`'s `clamp`), so it stays in view close to a tall prop.
- **Enemy navigation** (`world/navigation.ts`): obstacles are circles (`Obstacle`). Enemies walk straight at the player while the line is clear (with `MARGIN` to spare), else along a flow field: a Dijkstra from the player over a 0.5m clearance grid, one per size class, rebuilt at most one per frame. Every movement goes through `seek` in `enemyAI.ts`, which bends it round obstacles ahead (`steerClear`), so enemies curve round props instead of touching them. Ranged enemies and bosses only fire with a clear shot and walk round the obstacle otherwise. New obstacles need nothing more than an entry in the biome's `obstacles`, with `h`, the height of the prop's top: projectiles fly level and pass over obstacles lower than them, and an enemy's clear-shot check (`lineClear` with a height) agrees, so ranged enemies shoot over low cover. Movement ignores `h`.
- **Views** (V, runs only, not touch): `core/renderer.ts` has top-down, third and first person, gliding between them. The close views lock the pointer for mouse look through the run (the bank-or-continue choice too: B / C pick) (`wantPointerLock` in `core/input.ts`, taken while the last key press or click still counts as a user gesture, else on a click) and aim at the crosshair (`input.centerAim`): the foe under it, else the floor, else a point `aimRange` ahead. Losing the lock mid-wave pauses. In first person the body faces where the camera looks (`lookFacing`), so melee arcs and blocking follow the view, and only its arms, hands and weapons show (`entities/viewModel.ts`): the posed model (at its own scale) is moved so the camera sits just above its neck (the head rides the spine, so a lean never brings the shoulders under the camera), turned and tilted with the view and tipped back a little so the hands sit in frame, and the rest (pauldrons included) goes on a layer the camera doesn't draw. Every attack animates as in the other views, and **the middle of the view stays clear**: weapons, hands and spell effects are seen but kept off it, so what's ahead (the foes) is. `Model.firstPerson` switches a model's first-person poses, tuned by measuring where the weapon and hands land on screen (`FP_*` in `models/warrior.ts` and `models/mage.ts`): the warrior holds its weapons low in the corners, damps the stride's arm swing, swings lower and narrower with the blade up so the swing crosses the view broadside, places Power Strike, Twin Fangs and Bull Rush in the view itself (`holdInView` with `fromEyes` in `viewModel.ts`: a point of the camera's view in the posed model's world, each arm reaching by IK and the wrist turning the weapon onto a direction; `FP_CHOP`, `FP_CUT`, `FP_TUSK`): Power Strike crosses the blades over the top of the view as the charge builds and drives them down through it, Twin Fangs cocks each blade across the upper view and cuts it down to the opposite corner, Bull Rush draws the blades back, drives them ahead through the rush and flings them out to both sides as it lands (in every view: the charge's pose follows through for a moment after the rush, its weapons sweeping out with slash trails, and through the eyes the view widens with the speed, `kickFov`, as streaks of air rush at it); it raises its shield to just under the crosshair and hides its elbow fur; a two-hander (whose lower grip, the left hand's, would sit below the frame otherwise) is always placed in the view: at rest in both hands low on the right, the right elbow kept down so the forearm rises from the frame's edge, its swing sweeping the blade across the view like a wiper, Power Strike a raised guard on the right and the blow ahead; the mage holds the staff out to the right, narrows its bell sleeves and plays the free hand's gestures (cast, Void Lance, Aegis) in the left of the view, shifting the hand in the chest's space and reaching it with arm IK (`reachArm`). The third-person camera never pulls in towards the character: props and walls between it and the player dissolve instead (`core/seeThrough.ts`), so give a biome's prop and wall materials `seeThrough(m, 'prop')` (not the floor's).
- **Hostile bolts leave the caster's tip** (`fireBolt` in `enemyAI.ts` sends `model.tip`'s height with the `bolt` fx), then settle to the level `BOLT_Y` over their first 2.2m: hits and the clear-shot check (`lineClear`) assume that level. A caster's cast pose should still hold its tip near bolt height (the Sporecaller holds its pod out at the target), so the settling is only a few centimetres.
- **An enemy's blow lands when its animation says so:** the data's `windup` is the one clock. The AI fires the strike, slam or shot at `windup / (windup + recover)` of the action, and `Enemy.animate` hands the same share to the model (`ActionState.hit`, from the data, so a co-op guest's copy has it too). A model's `attack` / `slam` brings the blow down to connect *at* `hit` (raise until just before it, strike ending on it, recover after) and a caster's build-up peaks on it, so a new enemy's animation is written against `a.hit`, never against fixed shares of the action. The dodge window is unchanged: `meleeStrike` still checks range and facing when it fires.
- **Cooldowns are per skill id**, shared by every key the skill is bound to (the same spell may sit on several keys).
- **Asset paths:** Vite `base` is `./`. In `index.html` reference assets root-absolute (`/favicon.svg`) so Vite rewrites them; `check:pages` fails on paths that would break under `/last-stand/pr-preview/pr-N/`.
- Three.js 0.185: use `THREE.Timer` (not `Clock`) and `PCFShadowMap` (not `PCFSoftShadowMap`). Both old forms log deprecation warnings.
- **Co-op** (`src/net/`, rules in `game/run.ts`, UI in `ui/coop.ts`):
  - **Who runs what.** Every game moves and casts its own player and reports it (`pl` state at `COOP.sendRate`, `ev` actions: cast / fire / channel start and stop), in the lobby and in runs; the others replay it on a remote `Player` (`local` false, `replay()`, `updateRemote`). The host's game simulates the fight (enemies, damage, loot, waves, downs) and reports it (`net/sync.ts`: events every frame, a snapshot at the send rate); a guest's enemies are copies (`Enemy.net`) that don't think.
  - **Anything with gameplay effect goes through the checks in `net/role.ts`:** `hitEnemy` needs `by` (the casting player: its stats, the kill, leech) and only deals damage where `dealsDamage(by)`; `hurtPlayer(p, ...)` only where `simulates()`. Skill code runs on every game for its visuals, so keep its damage in `hitEnemy` and its hits on players in `hurtPlayer`.
  - **An enemy attack's visuals go through `fx()` in `enemyAI.ts`** (named `FX` entries with numeric arguments), which guests replay. New attack effects go there.
  - **Hooks, not imports:** the host reports through sinks set by `net/sync.ts` (`setSpawnSink`, `setFxSink`, `setNumberSink`, `setHitSink`, `runHooks`), so solo code has no network dependency and the relay library only loads when a room opens.
  - **Enemies target `e.target`** (the nearest active player, `nearestPlayer`), with a flow field per player slot. Use `G.players` (the local player first) for anything that concerns every player, and `G.player` only for the local one.
  - **A remote player has no staff light** (another point light would recompile every shader); its model is already warmed with the other classes.
  - The pause menu doesn't stop a co-op game (`G.menuOpen` with `G.paused` false; the local player goes `idle`), and a host in a background tab keeps stepping on a timer.
  - Bump `PROTOCOL` in `session.ts` (and the app id in `transport.ts` if the link itself changes) when the messages change: rooms only hold one version.
  - Test locally with two tabs of one browser and `?net=local` (a BroadcastChannel instead of relays): open a room in one, then open the invite link in the other.
- **Dev hooks:** in dev builds,
 `window.__G` (game state) and `window.__dev.spawnEnemy` are exposed for scripted testing and screenshots (stripped from production). Spawn enemies well away from the player (near the arena edge) or the player dies before the shot.

## Style

- TypeScript strict. Keep data (`src/data`) separate from behaviour, and type new data against `types.ts`.
- Match surrounding code: short header comment per file, sparse comments explaining *why*, compact one-line helpers where the file already uses them.
- Styles are SCSS in `src/ui/styles/`: one partial per area (`_hud.scss`, `_lobby.scss`, `_modals.scss`...), imported by `index.scss` in cascade order (later files override earlier ones; a moved rule can change what wins). Use the theme (`_theme.scss`: colours named by role, not by hue, so a theme change stays in that file; surfaces; `ui()` / `hud()` / `touch()` scale helpers) and the mixins (`_mixins.scss`: frame, gem, corner brackets, diamond rule, section heading) instead of copying values: plain colours as `var(--frame)`, translucent ones as `rgba($frame, .35)`. The loading screen's styles stay inline in `index.html`. UI scales via the `--ui` variable. Honour `prefers-reduced-motion` for decorative animation.
