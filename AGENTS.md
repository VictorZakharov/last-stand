# AGENTS.md

Guide for coding agents working on **Last Stand**, a browser 3D wave-survival ARPG (Three.js + TypeScript + Vite). `README.md` is the player/contributor overview; this file covers the things that aren't obvious from the code.

## Commands

```bash
npm install
npm run dev          # Vite dev server, http://localhost:5173
npm run typecheck    # tsc --noEmit (strict)
npm run build        # typecheck + production build into dist/
npm run check:pages  # after build: every asset path must work under the Pages base path
```

There is no test suite. Verify changes with `npm run build` and by playing the dev build in a browser. A hero's face is measured against a reference picture with `npm run facelab` (`tools/facelab/README.md`; once: `npm run facelab -- --setup`).

## Workflow

- **Every change goes through a PR** from a branch off `main`; never push to `main` directly. Each PR gets a live preview at `https://victorzakharov.github.io/last-stand/pr-preview/pr-N/` (sticky PR comment), forks included: `pr-preview-build.yml` builds the PR with a read-only token, then `pr-preview.yml` (a `workflow_run`, always the copy on `main`) checks the artifact's PR number against the API and publishes it. Never run PR code in `pr-preview.yml`. Fork runs need the maintainer's approval on every push (repo setting "all external contributors"), so nothing from a fork publishes unseen. Merging to `main` deploys production (`deploy-pages.yml`).
- **`main` is protected:** PRs only, merged with a merge commit (squash and rebase merges are disabled), and the branch must be up to date. **PR branches must be linear:** `git rebase origin/main` to update, never merge `main` into a branch. The `branch-policy.yml` check fails any PR containing merge commits. Merged branches are deleted automatically.
- Pages is served from an aggregated `gh-pages` branch: production at the root, open PR previews under `pr-preview/`. Don't switch Pages to "GitHub Actions only" and don't delete that branch.
- Keep PRs focused on one feature.
- **Prompt starts with `new issue:`** (fork workflow): run `scripts/issue.sh "title" "description"` with a title and description you write from the prompt, then do the work on the branch it creates. When done, run `scripts/commit.sh "PR title" "PR description"` instead of committing yourself, and reply with the PR link.

## Product rules

- **Core loop:** after *every* wave the player chooses Bank (keep all loot, leave) or Continue (harder wave, better loot). Dying loses all unbanked loot. Loot is **hidden until banked**: nothing drops on the floor, items go straight into the run's bag (`gainLoot` in `game/run.ts`), and the HUD shows only counts per rarity. The bank summary reveals the items one by one. Don't show what an unbanked item is (name, base, stats) anywhere. Don't change this without being asked.
- **The lobby floor** (`game/groundItems.ts`): gear given up in the lobby (dragged onto the game field, Shift-click, the touch sheet's Drop) is thrown on the floor, not deleted. Clicking its name (on touch: a tap shows the card, a second tap takes it) puts it back in the stash, if the class can use its base and the stash has room. In co-op every game shows every drop and the host decides who got one first (`gdrop` / `gtake` / `gtaken` in `net/session.ts`). Whatever is left on the floor is lost when a run starts, and a guest leaving the room leaves it to the host.
- **Everything is procedural.** No downloaded models, textures or audio: geometry, canvas textures, rigs/animation, VFX and WebAudio sfx are generated at runtime. Don't add binary assets. The exceptions are screenshots in `docs/` and the painted skill icons (`src/ui/skillArt/`, see below).
- **Originality:** this is open source. Skill, item, enemy and class names must be original. No Grim Dawn (or other game) names, trademarks or assets.
- The game is class-agnostic by name ("Last Stand"). More classes are planned, so keep class-specific code in class data, models and skills, not in the shared systems.
- **The UI must fit any screen size, desktop and mobile.** Anything that overflows or overlaps at some viewport size is a bug.
  - Scale: `--ui` for the lobby and modals, `--hud` for the in-run HUD, `--touch` for the touch controls (all set in `src/ui/scale.ts`).
  - Layouts: on desktop the lobby is a CSS grid `[left | center loadout | right]` with the panels against the screen's edges; each folds away to its edge on its own, leaving a labelled tab (`FOLDS` in `ui/menus.ts`, kept in `localStorage`). A fold tab stands outside its panel's frame, so a panel that scrolls does it inside (the left one's `.ml-body`), never on the panel itself. Short screens (phones held sideways, height ≤ 520) and upright tablets show one panel at a time, picked from `#lobby-rail`, and the camera view shifts so the character stays beside the panel (`lobbyViewShift`); they never fold a panel. Phones held upright get a "turn your device" overlay.
  - Check desktop at 1024×700 and 1920×1080, a phone at 844×390 and a tablet at 1180×820 and 820×1180 (Playwright with `isMobile` + `hasTouch`).
- **Installable, offline (PWA):** `public/manifest.webmanifest` plus a build plugin (`scripts/pwa.ts`, production builds only).
  - Install: Chrome and Edge fire `beforeinstallprompt`, and the lobby's Install link opens it. Safari (iOS) and Firefox never fire it, so on phones and tablets the link is always shown (unless already running installed) and opens `#install`, the add-to-home-screen steps for that platform.
  - The plugin renders the PNG app icons from `public/icon.svg` at build time (no binary assets in the repo) and writes `dist/sw.js`, which precaches every built file.
  - The worker's cache name is a hash of the build, so each deploy installs its own cache (fetched past the HTTP cache: Pages sends `max-age=600`) and takes over at once. It keeps the previous build's cache, so a page still running the old build can load its remaining chunks.
  - **A plain reload must show a new deploy:** the page is served network-first (the cached copy when offline or after 4s), the built files cache-first. `src/ui/pwa.ts` registers the worker (`updateViaCache: 'none'`, checking again when the tab comes back into view), shows the Install link and offers a reload in the lobby when a new build took over an open page (it asks the worker which cache it serves). Production's scope contains the PR previews, so the worker skips `pr-preview/` paths (each preview registers its own).
  - The pause menu shows the build (`__BUILD__` from `vite.config.ts`: commit, a preview's PR number, the build time in local time).
  - Test offline behaviour with `npm run build` + `vite preview`: the dev server has no worker.
- **Touch** (`src/ui/touch.ts`): touch mode (`body.touch`, `input.touchMode`) follows the last pointer used, and the browser's emulated mouse events are ignored in it.
  - Controls: a move stick on the left half and the skill buttons on the right. Tap casts at the nearest foe; drag aims by hand and casts on release. The basic attack and channels act while held.
  - Everything hover-only needs a touch path. Tooltips open on tap (`bindTooltip`); items open an action sheet (`openItemSheet`); skills are bound by tapping a key and then the skill. Drag and drop and Shift are desktop extras.

| `src/fx/` | CPU particle pools, a fixed pool of 8 point lights (`lights.ts`), transient effects (`effects.ts`) |
| `src/core/` | Renderer + post chain, input, audio, procedural textures & materials, game-time scheduler (`timers.ts`) |
| `src/net/` | Co-op: who simulates what (`role.ts`), the links (`transport.ts`: Trystero over Nostr relays, or `?net=local`), rooms, lobby and each player's own state (`session.ts`), the host's reports of the fight (`sync.ts`) |
| `src/ui/` | DOM HUD, lobby/menus, tooltips, loadout editor, item icons (inline SVG), skill icons (`skillArt.ts`), attributes; the stylesheets (`styles/`, SCSS) |

**Adding a class:** a data file in `src/data/classes/` registered in its `index.ts`, a model in `entities/models/`, and skills in `combat/skills/`. Class data also sets the lobby accent, the loadout panel title, the cast-point light and item base names; give new bases an icon in `ui/itemIcons.ts` and the class an equipment silhouette (`#equip .doll[data-class]` in `index.html`). Classes share no progress: each has its own profile. Switching class in the lobby rebuilds the `Player`, and `game/warmup.ts` builds every class's model at boot with everything it can wear shown at once (a hidden mesh compiles nothing), so a class switch or equipping anything compiles nothing.

**Adding a biome:** an entry in `data/biomes.ts` (enemy pool, boss, minimap), a builder in `world/` registered in `arena.ts`, and its enemies in `data/enemies.ts` with models in `entities/models/`.

## Gotchas

- **NaN means black lines or boxes on screen.** Bloom smears NaN/Inf pixels across the frame. Known causes: GLSL `smoothstep(a, b, x)` with `a >= b` (it's undefined, so write `1.0 - smoothstep(b, a, x)`), and `atan(0, 0)`. `renderer.ts` has a sanitize pass before bloom as a safety net; still fix the source.
- **Bright effects:** light adds up, so the final grade (`core/renderer.ts`) compresses it the way the eye does, and effects and their lights stay at full strength: don't dim single effects to fix a bright scene.
  - **Adaptation:** after bloom, the average light over a 16x9 and a 4x3 grid of the frame (`AreaPass`) is held under per-view targets (`ADAPT`, just above each view's ordinary scenes, which it leaves untouched) by compressing only the light above `ADAPT_BASE`, on a power curve. Never scale a whole pixel by its area's brightness (the dim ground round an effect darkens into a shadow around it), and don't adapt before bloom (effects drop under bloom's threshold and turn into flat discs with no glow). Above `HI_KNEE` the brightest channel eases towards `HI_CAP`, and in a large glare tone mapping keeps a bright pixel's colour (`HUE_*`, `GLARE_*`), so a big bright area stays green or blue instead of turning white.
  - **Distance:** effect materials dim with their distance from the camera (`nearGlow` in `core/materials.ts`: full strength from the top-down camera's distance, down to a quarter up close). `additive()`, the glow particles, projectile cores (a hostile bolt's is an orb of added light, with a pooled light when one is free; the spore throwers' are `fx/sporeOrb.ts`, the Rift Witch's and the Colossus's `fx/riftBolts.ts`: blended orbs, with added-light tails and halos), entity glows (`kit.glow`, the staff orb included; a hero's gear glows opt out) and the hit flash on bodies have it; wrap a new effect material in `nearGlow()`. The world's own glows don't.
  - **First person:** particles fade within 3.5m of the camera, a bolt flying at the camera shrinks away over its last metres (never pops out: nothing near the camera may switch off at once), and a cast leaves from `Player.castPoint` / `palmPoint`, which in first person are the weapon and hand in view. Keep lights off the camera: above the head, not at 2m. An effect round the body (a heal, a war cry) is seen from inside it: `Player.eyes` tells a skill it is, so it can put its particles where they're seen (a wider ring) and its light ahead of the view (`Player.lightAhead`; straight above, the weapons' steel mirrors it back into the view).
  - Nothing large may flash or pulse faster than about 1.5 times a second: 3+ flashes a second is a photosensitivity hazard. A hit's flash on a body is full at most every 0.7s (`hitFlash` in `util.ts`).
- **Creature geometry** (`entities/models/shapes.ts`): the enemies sculpt their bodies from tapered tubes, lathed limbs, noise-displaced shapes, leaves, fern fronds, branching boughs and winding strands on the rig's joints (`stripRig` removes the stand-in capsules), and `Sculpt` merges each joint's pieces per material into one mesh. `new Sculpt(kind)` caches the merged geometry per kind: later builds of the kind replay it (the builders return at once), so spawning stays cheap. That needs a deterministic build (seeded `mulberry`, never `Math.random`), and the shared geometry is never disposed (`userData.shared`, skipped in `Enemy.dispose`). The mage's bell sleeves are cloth (`models/sleeve.ts`: verlet particles on a tube, pinned by their top ring and hanging by gravity, hoop constraints keeping the section round, collided with the forearm and the body (`bodies`: torso, hips, skirt) and hanging outside the robe's skirts as they lie (`skirts`, `Skirt.pushOut`: kept off an ellipse the size of the hips, a bell hung into the robe draped out over the thighs, standing too); don't add a spring back to the animated shape, it makes them rubbery; each particle kept within the radius it was cut to round the forearm (so the arm never leaves the sleeve), a tether to the top ring and carrying the cloth along with part of the animation's motion stop it streaming off the arm at a run, and each row's slide up the forearm is capped (`SLIP`) so a turn or a lean never bares the hand; stepped in `animate` after the pose; `?cloth=0` holds them at the animated shape), and the warrior's fur sways (`models/furSway.ts`: a spring on each fur mesh in the vertex shader, weighted by the uv's v along the tuft; `?fur=0`). A piece that crosses a joint (a sleeve over the elbow, the neck into the head) goes through `Sculpt.skin` / `skinPair` instead of `add`: analytic skin weights from its position along the bone, one `SkinnedMesh` per joint for a hero (the first-person view hides by joint) and one per material on the root for a creature. Skinned meshes must keep their own copy of the material and their own `customDepthMaterial` (both done in `build()`), or a crowd pays for three rebuilding program parameters at every rigid/skinned switch; `Player.dispose` and `Enemy.dispose` free the skeleton and that copy. `?skin=0` puts them back on one joint. Pieces under 7 cm cast no shadow, and neither does a material passed to `Sculpt.glow` (glows, and leaves). For skin and cloth use `kit.rim` (a rim of light at glancing angles) rather than a physical material's sheen, which costs far more per pixel.
- **Hero models** (`models/mage.ts`, `models/warrior.ts`, `models/ranger.ts`) strip the rig's stand-in capsules and dress it from shared parts:
  - **Proportions are a real man's** (ANSUR II, the US Army's survey): 7.5 heads tall, shoulders, chest and hips at real widths plus the clothing or armour on them. Size new gear to that frame; exaggerated shoulders make the head look small.
  - `models/face.ts`: each hero's head as a signed distance field in millimetres, sculpted from average measurements, with a face shape (`FACES`) and colouring (`LOOKS`) per hero.
    - It's meshed by casting rays from inside the skull on a grid densest over the face (`headGrid`).
    - It's painted on the same grid in the loading workers (the `face` recipe in `core/pbr.ts`), so the texture fits a grid of any detail.
    - The rays start lower for the jaw and higher for the brow, so none skims along the skin. Past an overhang seen from the rays' start (under the brow, into the lid's crease) neighbouring rays meet the skin far apart; the points round such a stretched edge slide over the skin until they cover it (`relax`: the triangle between them would hang in the air as a dark streak), and the paint follows the moved points (`gridP`). A hollow inside the head still shows as streaks.
    - A face can be built on a measured mask (`FACES[...].mask`: both heroes', the mage's fitted to the real face nearest his old one, which had no picture: `dense.py`'s `nearest`) instead of blobs: its front's cross-section at each height a superellipse (`front` from the reference's profile, `half` from its front view, `side` where it's widest, `p` how square across, `pz` how its sides run back, `hollow` the soft hollow under the cheekbones), the nose, lips, brow, eyes and chin standing on it. Blobs joined by small blends left grooves, lumps and a snout; on a mask the cheekbones' blobs are left out too (they stood out of it with grooves round them). Don't tune the mask's knots by hand: `tools/facelab/fit.mjs` fits them (with the skull's, brow's, jaw's and chin's values) by least squares to the reference rebuilt in 3D and its front view's widths, then check the fit's clay views and curvature map.
  - `models/head.ts` builds the head: skin, eyes under lids, ears, hair cards (alpha-tested strands), a full beard for a face with `beardFull` (a volume over the skin: the skin's grid points lifted along their rays by face.ts's `beardLift`, leaning down below the mouth so it hangs, painted with the face's own paint, its edges sunk into the skin; and short tufts of cards over its lower part and past its edge, not round the mouth. Cast as part of the skin's own distance field, its hanging underside came out as a row of teeth; as long cards hung from the jaw it was a ruff, and draped over the robe's cowl a sheet that read as a liquid; facelab's `beard.ts` measures it)), and the neck. Hair comes in styles (`buildHead`'s `hair`): `swept`, combed straight back over the head and lying on it down to the nape, ending there and behind the ears (the mage: hung straight down from where they left the head, its locks made a bob over the ears, and a thick cap of combed fur under few locks read as a wig; facelab's `hair.ts` measures a wig's edge, the locks' ends and the ears covered) or `loose`, thick and tousled to the chin (the warrior: parted a little off the middle, locks rooted along a part line running back from the hairline (never at one point: roots meeting at a point show as a starburst from above), swept out over the temples and falling in waves past the ears, the front lifted up and back off the forehead, a few locks hanging beside the forehead to frame it), each lock a great-circle path over the head kept clear of the skin and the ears by the head's distance field (`pushOut`), shaded on its own (vertex colours: darker at the root, in its waves' hollows, in the deeper layers and where it lies close to the head), its cards a dense clump texture (solid in the middle, darker at its edges: thin strands of high contrast read as wood grain at a distance) with a tapered root. Locks start flush with the scalp behind the hairline (a lock's square root end shows as a block), and the cap over the scalp rises gradually from behind it, across a hairline running steeply down at the temples too (a step within a grid cell shows as a stair); under loose hair the cap is plain and dark, the shadow between the locks. Beyond the shape (`FACES`), a face is tuned by optional fields: `bridge`, `tip`, `browDrop`, `hollow`, `lowerW`, `masseter`, `beardLine`, `beardUnder`, `stacheCurve`, and the top of the neck under the jaw (`neckW`, `neckBack`, `neckBlend`: narrower, further back and blended less, the jaw stands out over it in a line, as a photo shows it; and the beard then grows on the jaw, not down the neck); a column neck (`neckCol`, the mage's: the head's skin ends in a column of the free neck's real section, an ellipse of a man's neck girth, ANSUR II's 0.69 of the head's, and the rig's neck keeps that section all the way up, crossing the head's skin by a millimetre each way at a seam that runs round it, `neckSeam`: low in front under a full beard's neckline, high behind so the neck bends above the collar; the neck's tube moves with the head near the seam through its own per-vertex skin blend, a `skinK` attribute `Sculpt.skin` reads, so the two skins stay matched as the head turns, is shaded with the normals of the tube without the crossing and has its grid's wrap seam welded, `weldNormals`; the face's pores and relief fade out down the column: a neck narrowing up to the jaw read as a cone, and the old seam showed as a step, a crease and a band of other colour; facelab's `neck.ts` measures the girth up the neck against the head's, the seam's step, crease, colour difference and relief, and skin showing through the collar); Each defaults to the old shape, so a hero not using one is unchanged. `Sculpt.add` / `skin` keep vertex colours only for a material that uses them. Tune a face against its reference with the face harness (`npm run facelab -- --ref <picture>`, `tools/facelab/README.md`): a studio render square to the face, lit as the reference is (`--key`), landmarks found the same way on both pictures and aligned by the eye corners, zoomed crops of each feature side by side and overlaid, and a report of proportions, the face's outline, the brows, colour and tone region by region (ours at the reference's resolution, warped onto its landmarks), the hair's outline, how it frames the forehead, its length, tones and the direction its strands run; the other views (side, back, from above) and which mesh shows where; not by screenshots judged by eye in a biome's light. Proportions can match while the look doesn't: when a face still doesn't look like its reference, add the measure that shows why to the harness before changing the face. The detector's points on our render follow its own idea of a face (they barely moved when our lips widened 13%, and drew an almond round an eye that rendered as a slot): measure ours from the render's own passes (the eyeball's mask) or its colours (the lips' width), not those points. Shape before colour: the clay views (no paint, no hair), a turnaround's three-quarter and side views (`--turn`: compared at the side panel's own turn, which needn't be a profile), landmarks placed by hand on the reference for what a beard and hair hide (`--points`: the jaw's angles and line, the face's sides), the relief (whether bones stand out, and whether that is the shape or the paint) and the surface everywhere (`--turn` also rebuilds the reference in 3D with a statistical model of real faces and maps ours against it, against the real face nearest ours, and our skin's curvature: outlines and points alone left the surface between them free, and it came out unlike a face); Armour that comes off is built on meshes of its own (a `Sculpt` of its own), never merged with what stays.
    - `toGroup` places anything by the head's anatomy (mm).
    - `surface` gives the skin in any direction, and the helmet and hat are shaped with it.
  - `models/hands.ts`: three-jointed fingers. A hand holding something stays on its wrist: it turns so the handle runs across the palm (its length along the forearm, the wrist bending only as the handle needs), and the weapon is seated in that palm (`seat`, a grip joint moved to where the fist closes, whenever its turn changes). `hold()` then closes each finger snugly round the handle (each segment bends just until its end touches it, whatever its radius), the thumb over them from the other side. It does nothing while the body is off the ground (an enemy rising at spawn) or dying, and restarts under the hips after a teleport (`reset()`). Everything is local and visual: a co-op copy computes it from the motion it replays, so there is no protocol change. **Where a standing body puts its feet is the pose's to say** (`legs.stance(i, x, z, turn)`, in the root's own frame; the heroes' `*_FEET`): a foot further than a few cm from its spot steps there, one at a time, its knee bending over the way it points, so an idle's stance (side-on, the rear foot turned out) and an attack's step in are real steps; moving, the gait ignores it. The pose then moves the pelvis freely (`body.position`, the hips' turn and roll: a weight shift, a lunge, a crouch) and the planted feet hold. A pose that moves the body faster than feet can step (a dash's lunge or charge) or spins faster than they could follow (Steel Tempest) owns the legs: it passes a lower `weight` to `legs.update` (the warrior's `legOwn`), the lean, twist and pelvis fade with it, and the feet restart where the pose has them when it gives them back; one leg alone goes through `legW` (`ownL` / `ownR`), the other staying planted. Enemies skip the leg IK out of the view and, on Low, beyond `ikRange` from the player (`LegIK.active`); film a new skill side on with and without `?ik=0`. `LookAt` turns the chest, neck and head onto the nearest foe (heroes) or the target (enemies), from the body's position and facing alone; not through the eyes (the camera rides the head). The heroes run it inside `animate` before the leg IK and the cloth (`AnimState.look`), since the chest's share moves the arms the sleeves and cape follow; enemies after `animate`.
  - **Hero moves are full-body and keyed** (`models/motion.ts`): an attack is written as keyframed curves over its progress (`curve(keys, k)`, a monotone cubic: an overshoot or a hold is a key of its own), one per channel, and moves the whole body, not just the arms: a wind-up (the weight back onto the rear foot, the hips and chest coiling away), the blow led from the ground up (the hips turn first, the spine and chest after, the arm and wrist last: the same curve read a few hundredths earlier for each joint down the chain), the weight forward and down into it, a follow-through past the hit, the other arm countering and the head kept on the foe. Keep a move's hit where the skill fires (the swing's tip crosses the arc from 0.55 to 0.85 of the cast, in step with the trail). `PoseFade` crossfades every cut between poses (an action starting, restarting or ending: from the pose shown just before, over a fifth of a second or so, slower out of a blow that should be seen to recover), so a move may end on its follow-through and let the fade bring it home. A short cast's end (a throw, a blow, a roar) is held a moment after the cast is over and then eased out (`TAIL` / `TAIL_OUT` in each hero model; moving off or another action cuts it), so it is seen without slowing the gameplay. The healing draught is drunk (`models/flask.ts`: the free hand takes a flask from the belt and arm IK lifts it to a mouth point on the head, from where each model holds it, `DrinkHold`; the warrior's shield hangs from that forearm before the chest meanwhile, a second weapon is worn on the belt (`DRINK_SHEATHED`: in a leather frog at the left hip, a sword by its guard with the blade raked back along the thigh, an axe or mace head up; `Weapon.hang`) and drawn again, a two-hander lets go of its lower grip, and the mage's sleeve is pushed back up the arm). Its beats are smooth keyed curves (`HIP`, `LIFT`, `TIP`, `OUT`), the flask aimed from the planned wrist, not the moving one (check with a per-frame speed and turn-rate probe). It is a `freeMove` cast: no other skill while it lasts, but full speed and facing the way the hero goes. A dash may pace itself (`DashOpts.pace`: Bull Rush braces, accelerates and skids, covering the same distance). The idles are alive: a stance with the weight shifting from foot to foot (the pelvis swaying over them, the hips tipping, the shoulders answering), breathing in the shoulders, the weapons at the ready, a blade held edge on to the foe in a neutral grip, thumb up and palm in, the wrist nearly straight (`REST_ARM`, `REST_TWO`: the forearm angled down so the blade rises from the fist; measure the wrist's bend from the forearm in the hand's frame) (`MOUNT`: in third person every weapon sits in its fist as a real one does, its flats along the palm and its edge or bit out over the knuckles; a move that must lead with the edge rolls the forearm, `edgeOn` about a blade along the arm: palm up on a forehand swing, down on a backhand, `SW_ROLL`, `FANG_ROLL`; never turn a blade held across the forearm that way, it bends the wrist instead. Check with a probe of the flat's normal against the tip's motion and the palm's against the flat). First person keeps its own hand-placed poses (`FP_*`); the full-body versions are third person only. Check a move with a frame-exact film (the game paused, `animate` stepped through the action by hand) from the side and the front.

- **Loading screen:** `#loading` (markup, SVG logo and styles) is inline in `index.html` so it paints before the bundle. Its exit (`ui/logoWind.ts`) snapshots the SVG letters (the font is inlined, since an SVG image can't load web fonts) onto the device pixel grid, turns every pixel into a WebGL point, blows them away and gathers them into the lobby logo (`#menu .logo-art`, kept hidden until then). The motion is closed-form in the vertex shader. No copy of a logo is ever shown at rest, so the two never visibly swap: a point is drawn only once the wind lifts it (the real letters are clipped away just behind the front), and landing points take the colours of a snapshot of the lobby logo, which is then uncovered left to right under them. - **Don't scale a centred box in or out** (the modals' `pop` is a fade alone): centred, its position falls on a fraction of a pixel, which a transform draws as it is, and as the transform ends the box jumps up to a whole pixel, a visible 1 px shift. Measure with the pause probe: the box a frame before its animation ends against it at rest.
- **Canvas size:** `fitViewport` in `core/renderer.ts` fits the canvas, render targets and camera on resize *and* every frame, and ignores zero sizes. Moving the window between monitors can report a zero height mid-move (zero-sized render targets: a black screen until the next resize) or change the pixel ratio with no resize event. Read the window size through it, not `innerWidth`/`innerHeight` directly, in anything that feeds the camera.
- **Quality presets** (`data/quality.ts`, pause menu, Auto by default) change pixel ratio, MSAA, shadow map size and which small character parts cast shadows, all live and without shader changes. Keep new settings in that category, or they cause compile hitches when switched.
- **Static shadow casters are baked:** `bakeStaticShadows()` in `world/props.ts` merges every non-instanced caster of a biome into one shadow-only mesh. Arena props must not move after the arena is built. The bake keeps positions only, so an alpha-tested mesh (leaf cards) must not cast from a single mesh: it would cast solid quads. Instanced ones cast properly (three's shadow pass honours `alphaTest`).
- **Biomes:** every biome is built at boot into its own group, and switching only toggles visibility and sets the shared lights, fog and environment (`BiomeLook`), so it's instant. Boot warms up the lobby in every biome. The lobby choice is a cookie (`last-stand-biome`); Random rolls a biome when a run starts.
- **Cape:** the cloth steps in a web worker (the solver's own `WebGlCapeWorkerPool`); the main thread applies the latest result, shifted onto the current neckline to hide the round trip. Without workers it steps on the main thread within a per-frame budget, so a slow frame can't snowball into more catch-up steps. `SkeletonCape.update` must call `sim.syncGeometry()` after new particle positions arrive, or the cape freezes at spawn. The floor shim imports `world/ground.ts` directly (a worker shares no state with the page). Colliders are capsules built from rig joints in each class model (`models/mage.ts`, `models/warrior.ts`), the mage's staff's haft too. A collider follows what it stands for: the mage's pauldrons on the shoulder joints, turning with the arms as they do (they stood 2 cm out past the shoulders' and arms' capsules and came through the cape as he set off), his sleeves from above the elbow to the bell's hem as it hangs (a point the model moves each frame after the bells step; with nothing below the elbow the free arm's bell swung back through the cape at each step), the shoulder blades' across the chest, not between the shoulder joints (a raised arm turned its ends 4 cm forward and the tunic came through). Each joint a collider is on must stay where it should through every pose; a radius is in world units, not scaled with the model (`root.scale`). The solver pushes the cloth only towards the cape's back (out of a capsule behind its first end), so a pole swept through the cloth faster than that stays through it, and a pole pointing straight back acts only at its tip: a pose keeps a held weapon out of the cape's way (the mage aims his staff with its haft angled out, `STAFF_OUT`: aimed straight at a foe, a metre of it reached back through the cape). Measure with a deterministic probe (a fixed 1/60 s clock, the cape stepping on the main thread on it, scripted input): the share of frames in which the haft crosses the cloth while strafing and shooting. **The pinned neckline must stay outside every collider**, in every pose: a cloth triangle pinned along one edge and pushed out of a capsule moves only its free corner, by the push over that corner's share of the contact, which near the pinned edge throws it metres; the solver then resets the cape (a particle 5 m off), and a cape reset several times a second jerks up and down (the mage's over his tunic: its neckline nearer the neck than over the robe, inside the robe-sized upper torso and shoulders). A capsule's rounded end reaches up by its radius, so a body that is deeper just below the neckline than at it (a broad upper back) is fitted by a horizontal capsule across the shoulder blades, not a taller torso. Measure in the probe: the solver's resets from its invalid-state guard, how deep the pinned row sits in each collider as the solver samples it, and how much of the cloth lies inside the body (points inside each quad, a ray out of the body along the cape's back meeting a surface facing the same way; three's raycast skips a front-sided material's back faces, so make them double-sided for the test), and the body coming through it as surfaces crossing: per frame, the length of the lines where the body's triangles cross the cape's, by the part of the body (an upper arm with its pauldron, a forearm with its sleeve, the chest) and the cape's rows, in every scenario (standing, walking, backing up, strafing, diagonals, each with shots) robed and in the tunic; a cape that comes through only as the body sets off or at the back of a swing shows in a few frames, not in a share of time sampled now and then.

- **Gear-driven skills and block:** `Player.gear` comes from the equipped items: weapon base, two-handed (`ClassDef.twoHanded`), shield (an off-hand with Block Amount), and a weapon in the off-hand (`ClassDef.dualWield`: a one-hander fits the off-hand slot, and its implicit counts at `OFFHAND_WEAPON`). With two weapons the model's swings alternate hands, and `tip` moves to the swinging weapon. - **Breakable props** (`world/destructible.ts`): everything standing in the arena has hit points and breaks under focused fire (the walls and the boundary don't): player and hostile bolts (`Projectile` world collision), the Void Lance beam, melee swings (`sweep`, whether or not they found a foe) and every area skill (`hurtPropsIn(player, x, z, radius, amount)`: Starfall, Glacial Nova, Maelstrom, Tempest, Crescent, Iron Bellow, Bull Rush; a new area skill calls it next to its `hitEnemy` loop). `PROP_DAMAGE` sets the weights, each prop its own `hp`. A glow is only an emissive colour or map on a standard material, and every program is warmed in `warmup.ts`. A damaged prop shows a `.pbar` (a notched stone gauge, not the foes' red bar) for 5s after the last blow, then fades; it sits no higher than 2.2m and is clamped to the screen (`addAnchored`'s `clamp`), so it stays in view close to a tall prop.
- **Enemy navigation** (`world/navigation.ts`): obstacles are circles (`Obstacle`). Enemies walk straight at the player while the line is clear (with `MARGIN` to spare), else along a flow field: a Dijkstra from the player over a 0.5m clearance grid, one per size class, rebuilt at most one per frame. Every movement goes through `seek` in `enemyAI.ts`, which bends it round obstacles ahead (`steerClear`), so enemies curve round props instead of touching them. Ranged enemies and bosses only fire with a clear shot and walk round the obstacle otherwise.   - **Drawing:** the picture fills the slot (`.slot.art`), and the slot's frame and states (active, out of energy) are drawn again over it from its own `box-shadow` (`::after`, `inherit`), under the cooldown and the key. In the key diagram (How to play, the pause menu) a skill's picture fills its whole key, and the key, the skill's name and "hold" stand over it in a dark glow (at a keycap's icon size it was too small to read).
  - **Loading:** every picture is fetched at boot, and the service worker precaches them with the build.
  - **A new icon** matches the set, which is simple and bold.
    - **Simple:** one subject, or two or three of the same object at most; clean silhouettes with smooth shading; pure black to the edges, with nothing scattered round it (no sparks, leaves, rings or ground).
    - **Bold:** big, filling about 80% of the square; chunky proportions (thick shafts, big heads); a strong saturated glow in the skill's `icon.color` lighting it.
    - **Padded:** the touch buttons are round, so 99.5% of an icon's light must lie inside the circle they draw, and its content at least 4% clear of the square's edges. The ranger's arrows ran corner to corner and the circle cut up to 16% of their light. On a black background a picture is padded exactly by shrinking it onto a larger black square.
    - **Coloured apart:** each skill of a class in a colour of its own, as the warrior's and mage's are, with `icon.color` (the tooltip's name, the key diagram's glow) set to match.
    - **Judged at slot size:** compare it with the others shrunk to 60 px. The ranger's first set was crowded (vines, sparks, a stag behind the reticle), and the next came out as thin, pale arrows that faded beside the others.
    - **Tooling:** the ranger's were made with Codex CLI's image generation, attaching the simplest icons of the set (and the ranger's accepted ones) as style references (`codex exec -i <icon> ...`).
- **Asset paths:** Vite `base` is `./`. In `index.html` reference assets root-absolute (`/favicon.svg`) so Vite rewrites them; `check:pages` fails on paths that would break under `/last-stand/pr-preview/pr-N/`.
- Three.js 0.185: use `THREE.Timer` (not `Clock`) and `PCFShadowMap` (not `PCFSoftShadowMap`). Both old forms log deprecation warnings.
- **Co-op** (`src/net/`, rules in `game/run.ts`, UI in `ui/coop.ts`):
  - **Who runs what.** Every game moves and casts its own player and reports it (`pl` state at `COOP.sendRate`, `ev` actions: cast / fire / channel start and stop), in the lobby and in runs; the others replay it on a remote `Player` (`local` false, `replay()`, `updateRemote`). The host's game simulates the fight (enemies, damage, loot, waves, downs) and reports it (`net/sync.ts`: events every frame, a snapshot at the send rate); a guest's enemies are copies (`Enemy.net`) that don't think.
  - **Anything with gameplay effect goes through the checks in `net/role.ts`:** `hitEnemy` needs `by` (the casting player: its stats, the kill, leech) and only deals damage where `dealsDamage(by)`; `hurtPlayer(p, ...)` only where `simulates()`. Skill code runs on every game for its visuals, so keep its damage in `hitEnemy` and its hits on players in `hurtPlayer`.
  - **An enemy attack's visuals go through `fx()` in `enemyAI.ts`** (named `FX` entries with numeric arguments), which guests replay. New attack effects go there.
  - **Hooks, not imports:** the host reports through sinks set by `net/sync.ts` (`setSpawnSink`, `setFxSink`, `setNumberSink`, `setHitSink`, `runHooks`), so solo code has no network dependency and the relay library only loads when a room opens.
  - **Enemies target `e.target`** (the nearest active player, `nearestPlayer`), with a flow field per player slot. Use `G.players` (the local player first) for anything that concerns every player, and `G.player` only for the local one.
  - **A remote player has no staff light** (another point light would recompile every shader); its model is already warmed with the other classes.
  - The pause menu doesn't stop a co-op game (`G.menuOpen` with `G.paused` false; the local player goes `idle`), and a host in a background tab keeps stepping on a timer.
  - Bump `PROTOCOL` in `session.ts` (and the app id in `transport.ts` if the link itself changes) when the messages change: rooms only hold one version.
  - Test locally with two tabs of one browser and `?net=local` (a BroadcastChannel instead of relays): open a room in one, then open the invite link in the other.
- **Dev hooks:** in dev builds,
 `window.__G` (game state) and `window.__dev.spawnEnemy` are exposed for scripted testing and screenshots (stripped from production). Spawn enemies well away from the player (near the arena edge) or the player dies before the shot.

## Style

- TypeScript strict. Keep data (`src/data`) separate from behaviour, and type new data against `types.ts`.
- Match surrounding code: short header comment per file, sparse comments explaining *why*, compact one-line helpers where the file already uses them.
- Styles are SCSS in `src/ui/styles/`: one partial per area (`_hud.scss`, `_lobby.scss`, `_modals.scss`...), imported by `index.scss` in cascade order (later files override earlier ones; a moved rule can change what wins). Use the theme (`_theme.scss`: colours named by role, not by hue, so a theme change stays in that file; surfaces; `ui()` / `hud()` / `touch()` scale helpers) and the mixins (`_mixins.scss`: frame, gem, corner brackets, diamond rule, section heading) instead of copying values: plain colours as `var(--frame)`, translucent ones as `rgba($frame, .35)`. The loading screen's styles stay inline in `index.html`. UI scales via the `--ui` variable. Honour `prefers-reduced-motion` for decorative animation.
