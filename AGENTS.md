# AGENTS.md

Guide for coding agents working on **Last Stand**, a browser 3D wave-survival ARPG (Three.js + TypeScript + Vite). `README.md` is the player/contributor overview; this file covers what applies across the game.

**Every directory has an AGENTS.md of its own**, with what is relevant there: what its code does, its gotchas, what each was measured against and how it went wrong before. Before changing code, read the AGENTS.md of each directory on the way down to it. A `CLAUDE.md` beside each one imports it, so Claude Code loads it as it reads a file there. What is learned about an area goes in its directory's AGENTS.md; this file keeps what applies across the game. The heroes' heads, gear, bow and legs have longer notes in `docs/agents/`, which `src/entities/models/AGENTS.md` says when to read. Keep every one of these files under 120k characters (every agent's session loads this one whole, and Claude Code warns past 150k): when one nears that, move its largest area into a directory or a note of its own.

## Commands

```bash
npm install
npm run dev          # Vite dev server, http://localhost:5173
npm run typecheck    # tsc --noEmit (strict)
npm run build        # typecheck + production build into dist/
npm run check:pages  # after build: every asset path must work under the Pages base path
npm run stalls       # the game in the installed Chrome, traced: the browser's own stalls (tools/stalls/README.md)
npm run icons -- sheet  # every class's skill icons side by side at a slot's size (check, add: tools/icons/README.md)
npm run music -- loops piece.wav  # where a piece can loop; make, seam: the game's tracks (tools/music/README.md)
```

The game has no test suite. Verify changes with `npm run build` and by playing the dev build in a browser.

- **Pictures and measures of the game go through the lab** (`tools/lab/AGENTS.md`: every command in a line and how to write one; `tools/lab/COMMANDS.md`: each in full). `npm run lab:serve` boots each command's page ahead of it; every command runs on a fresh boot and gives the same result every time; `--ab` runs it on `origin/main` too and says which lines and pictures differ; `npm run lab -- check --ab` runs every hero's checks of a change to how they move, side by side; `npm run lab -- live` keeps a page between steps for trying a pose or a look by hand (pictures in under a second, in any look: wireframe, faces, parts and where each is on screen, skeleton; a reference laid over). The lab's own code has unit tests: `npm run lab:test`.
- **Every harness is permanent.** Write a new measure in the lab (`tools/lab/examples/handSpeed.ts` shows its parts: the state it measures checked to have happened, a canary it must catch), never as a script with a boot and a clock of its own, and keep it: from its first use it is a lab command, or part of one that measures the same thing, never a probe left in `.tmp`. The probes and films these files name that aren't in the repo (the bow probe, `legdet`, the zigzag and aim probes, the DPS probe...) were such scripts: each is a measure to port into the lab the first time it's needed again, as the carry's and the range probe's were.
- A hero's face is measured against a reference picture with `npm run facelab` (`tools/facelab/README.md`; once: `npm run facelab -- --setup`). The tools and how their code is written: `tools/AGENTS.md`.

## Workflow

- **Every change goes through a PR** from a branch off `main`; never push to `main` directly. Each PR gets a live preview at `https://victorzakharov.github.io/last-stand/pr-preview/pr-N/` (sticky PR comment), forks included: `pr-preview-build.yml` builds the PR with a read-only token, then `pr-preview.yml` (a `workflow_run`, always the copy on `main`) checks the artifact's PR number against the API and publishes it. Never run PR code in `pr-preview.yml`. Fork runs need the maintainer's approval on every push (repo setting "all external contributors"), so nothing from a fork publishes unseen. Merging to `main` deploys production (`deploy-pages.yml`).
- **`main` is protected:** PRs only, merged with a merge commit (squash and rebase merges are disabled), and the branch must be up to date. **PR branches must be linear:** `git rebase origin/main` to update, never merge `main` into a branch. The `branch-policy.yml` check fails any PR containing merge commits. Merged branches are deleted automatically.
- Pages is served from an aggregated `gh-pages` branch: production at the root, open PR previews under `pr-preview/`. Don't switch Pages to "GitHub Actions only" and don't delete that branch.
- Keep PRs focused on one feature.
- **The relay server's deploy** (Dokci, `.dokci/AGENTS.md`) must keep its route on trusted TLS: never bypass certificate verification or add a public-relay fallback.
- **Don't waste compute: a check run over and over takes minutes, not half an hour.** The lab is run hundreds of times over a task, so a round's cost multiplies. Before running a suite again and again, ask what one round costs and what of it is wasted, and fix the tool first: profile it (`--profile`), keep what can't change (an A/B's other side is kept by its commit, `out/ab-cache`), run independent commands side by side (`npm run lab -- check --ab`: every hero's gait, stops and ranges, the ranger's feet and carry, in sessions of their own), skip what the measure never reads (films, pictures), and while iterating run only the scenarios a change can touch (`--scenarios`, `--classes`). Run one command at a time, both sides each time, the mage's cape (the heroes had capes then) stepped throughout and each gait scenario run again for a film, the same check took 31 to 35 minutes a round, and was run five times in a day.
- **When the work stops being smooth, stop and fix how it's done.** Running into the same wall again is the sign: a probe rewritten for each task, a result that turns out to have measured nothing, a restart before every measure, a hand-made swap to compare with `main`, a constant edited and reloaded over and over. Take the time then to build the proper tool, harness or refactor, typed, reused and documented in `tools/`, instead of one more quick script that might work. This repo keeps a high quality bar, and its tools are held to it too: an iteration should take seconds and its results should be trustworthy. (On the bow's carry, seven one-off probes in `.tmp` each re-copied the boot, the fixed clock and the ray tests; two reported clean while measuring nothing, and one issue took hours. `tools/lab` replaces them.)
- **A pose is decided as a person would hold it, then looked at as the player sees it, and only then measured** (`src/entities/models/AGENTS.md`): clip measures check a natural pose; they never choose one.
- **Check every deletion two or three times before running it**, however sure it looks, and whoever asked for it: a folder of scratch, a tool's `out/`, a branch, a file. List what it holds, and for each thing in it ask where it came from, where else it exists and what needs it: search the repo and the session's history for paths into it, and keep whatever can't be made again (a picture or piece the owner saved there, a reference, an original an asset was made from). Then delete only what was checked, by name, and say what was kept and why. Scratch folders aren't all scratch: the owner saves files into `.tmp` to hand them over (what can go and what to keep: `tools/AGENTS.md`'s Cleaning up). (Cleaning 16 GB out of `.tmp`, the references the faces were tuned against, which the owner had saved there, went with it, and came back only from the session's logs.)
- **A/B against `main` without losing work:** commit what you have first (a `wip:` commit, squashed or reworded before the PR), and only then swap files: `git checkout origin/main -- <files>` to measure main, `git checkout HEAD -- <files>` to come back, and `git status` clean after. Never run `git checkout <ref> -- <file>` (or `git restore`, `git reset --hard`) over uncommitted changes, and don't use `git stash` as the swap: with a clean tree it stashes nothing and both sides of the A/B measure the branch, and checking a file out before stashing it throws its changes away (both happened, and an afternoon's tuning was lost).
- **Prompt starts with `new issue:`** (fork workflow): run `scripts/issue.sh "title" "description"` with a title and description you write from the prompt, then do the work on the branch it creates. When done, run `scripts/commit.sh "PR title" "PR description"` instead of committing yourself, and reply with the PR link.

## Product rules

- **Core loop:** after *every* wave the player chooses Bank (keep all loot, leave) or Continue (harder wave, better loot). Dying loses all unbanked loot. Loot is **hidden until banked**: nothing drops on the floor, items go straight into the run's bag (`gainLoot` in `game/run.ts`), and the HUD shows only counts per rarity. The bank summary reveals the items one by one, the most valuable first, each in its place in the list. Don't show what an unbanked item is (name, base, stats) anywhere. Don't change this without being asked.
- **The lobby floor:** gear given up in the lobby is thrown on the floor, not deleted, and is picked up again until a run starts (`src/game/AGENTS.md`).
- **Everything is procedural.** No downloaded models, textures or audio: geometry, canvas textures, rigs/animation, VFX and WebAudio sfx are generated at runtime. Don't add binary assets. The exceptions are screenshots in `docs/`, the painted skill icons (`src/ui/skillArt/AGENTS.md`) and the music (`src/audio/music/AGENTS.md`).
- **Originality:** this is open source. Skill, item, enemy and class names must be original. No Grim Dawn (or other game) names, trademarks or assets.
- The game is class-agnostic by name ("Last Stand"). More classes are planned, so keep class-specific code in class data, models and skills, not in the shared systems.
- **The UI must fit any screen size, desktop and mobile.** Anything that overflows or overlaps at some viewport size is a bug. The UI is a share of the screen whatever the OS's scaling; check every change at the sizes `src/ui/AGENTS.md` lists (its scales, its layouts, `npm run lab -- ui --screens`).
- **Installable, offline (PWA):** a plain reload must show a new deploy. Players meet a new deploy under the previous one's worker: check a change to the worker, or to what the page asks of another host, with `npm run lab -- pwa`. The worker and its caches are `scripts/AGENTS.md`, the page's side `src/ui/AGENTS.md`.
- **Touch:** everything hover-only needs a touch path (`src/ui/AGENTS.md`).

## Architecture

Each directory below has an AGENTS.md saying more.

| Path | Contents |
| --- | --- |
| `src/types.ts` | Shared types: data definitions (`SkillDef`, `ClassDef`, `EnemyDef`, `Item`...) and runtime (`Model`, `Effect`...) |
| `src/data/` | Pure tuning data typed against `types.ts`: classes & skills, enemies, biomes (roster, boss per biome), items/affixes, waves, `balance.ts` (camera, arena, run constants) |
| `src/combat/skills/` | Skill behaviours, registered in `index.ts` (`SKILL_IMPLS`) and referenced from class data by `impl` name. Instant: `cast()`. Channel: `start/tick/stop` with a typed state object. Use `Needs<'field'>` to require optional `SkillDef` tuning fields |
| `src/entities/models/` | Procedural models, registered in `index.ts` (`MODELS`); `rig.ts` = shared humanoid skeleton + pose helpers |
| `src/game/run.ts` | Wave flow, scoring, loot rolls, bank / continue |
| `src/world/` | `arena.ts` builds every biome at boot and switches between them; one builder per biome (`crypt.ts`, `forest.ts`), shared pieces in `props.ts` (the night and day skies too), the Thornwood's leaf-card foliage in `foliage.ts`, its trees grown by ez-tree in `ezTrees.ts` |
| `src/loot/` | Item generation (base names and excluded stats per class), save slots (`saveSlots.ts`), persistent profiles, one per class and save slot (`localStorage` `last-stand.profile.<classId>.v1`; the pre-class `last-stand.profile.v1` migrates to slot 1's mage), the lobby's class (cookie `last-stand-class`), skill loadout (cookie `last-stand-loadout-<classId>`; a class with gear-driven skills keeps one per weapon style, `last-stand-loadout-<classId>-<style>`). Slots 2 and 3 put `s2` / `s3` after the `last-stand` prefix of each name |
| `src/fx/` | CPU particle pools, a fixed pool of 8 point lights (`lights.ts`), transient effects (`effects.ts`) |
| `src/core/` | Renderer + post chain, input, audio, procedural textures & materials, game-time scheduler (`timers.ts`) |
| `src/net/` | Co-op: who simulates what (`role.ts`), the links (`transport.ts`: our relay server, `server/relay`, or `?net=local`), rooms, lobby and each player's own state (`session.ts`), the host's reports of the fight (`sync.ts`) |
| `src/ui/` | DOM HUD, lobby/menus, tooltips, loadout editor, item icons (inline SVG), skill icons (`skillArt.ts`), attributes; the stylesheets (`styles/`, SCSS); the world's overlays, drawn in WebGL over the frame (`overlay/`, placed by `floaters.ts`) |
| `src/state.ts` / `src/events.ts` | Typed global state `G` and a typed event bus |

**Adding a class:** a data file in `src/data/classes/` registered in its `index.ts`, a model in `entities/models/`, and skills in `combat/skills/`. Class data also sets the lobby accent, the loadout panel title, the cast-point light and item base names; give new bases an icon in `ui/itemIcons.ts` and the class an equipment silhouette (`#equip .doll[data-class]` in `index.html`). Classes share no progress: each has its own profile. Switching class in the lobby rebuilds the `Player`, and `game/warmup.ts` builds every class's model at boot with everything it can wear shown at once (a hidden mesh compiles nothing), so a class switch or equipping anything compiles nothing. A switch builds the new hero from scratch, all but his head: its geometry is made once per face, hair and detail (`once` in `models/head.ts`: the hair's cards were 60% of a build, which took 95 to 170 ms, now 30 to 70) and shared by every build after (`userData.shared`, which a model's dispose keeps: `disposeGeometries` in `rig.ts`). Time a switch in the lab's lobby (abandon the run its set-up starts) by the browser's own clock, `__labClock.realNow`.

**Adding a biome:** an entry in `data/biomes.ts` (enemy pool, boss, minimap), a builder in `world/` registered in `arena.ts`, and its enemies in `data/enemies.ts` with models in `entities/models/`. It adds exactly 6 point lights and keeps the dais and the gates where every biome has them (`src/world/AGENTS.md`).

Outside `src/`: `tools/` (the harnesses: the lab, the face harness, the icons, the music, the stalls), `server/relay` (the co-op relay), `scripts/` (the build's and the workflow's), `public/` (served as it is), `docs/` (notes, research, screenshots), `.github/workflows` (PR checks, previews, production) and `.dokci` (the relay's deploy).

## Across the game

- **NaN means black lines or boxes on screen.** Bloom smears NaN/Inf pixels across the frame. Known causes: GLSL `smoothstep(a, b, x)` with `a >= b` (it's undefined, so write `1.0 - smoothstep(b, a, x)`), and `atan(0, 0)`. `renderer.ts` has a sanitize pass before bloom as a safety net; still fix the source.
- **Bright effects:** light adds up, so the final grade (`core/renderer.ts`) compresses it the way the eye does, and effects and their lights stay at full strength: don't dim single effects to fix a bright scene. Wrap a new effect material in `nearGlow()` (`core/materials.ts`), keep lights off the camera in first person, and nothing large may flash or pulse faster than about 1.5 times a second (3+ flashes a second is a photosensitivity hazard). How the grade adapts, how effects dim with distance and what first person changes are in `src/core/AGENTS.md`; measure an effect with `npm run lab -- cast <skill>`.
- **Foes are drawn in crowds** (`entities/models/crowd.ts`): every creature of a kind is one instanced draw a material. A foe's look changes through its kit's uniforms (`kit.u`: dissolve, frost, char, hit, edge) and its materials' `emissiveIntensity` alone; a colour, a hidden mesh or a swapped material on one foe shows on none (`src/entities/models/AGENTS.md`).
- **Point lights:** use the pooled slots in `fx/lights.ts`. Never add ad-hoc `PointLight`s, because changing the light count recompiles every shader.
- **Shaders compile at load, never mid-game.** `core/shaders.ts` pins every compiled program (three.js would delete it when its last material is disposed) and `game/warmup.ts` renders one of every enemy, effect, drop and skill visual at boot. A skill with its own materials must return sample meshes from its `warm()` hook. The perf overlay (pause menu) shows `Shaders N (+M)`: M must stay 0 during play, and the copied report says what compiled late.
- **Keep loading in short chunks:** a window moved to another monitor shows black until the main thread can paint it, so boot work yields between steps (biomes, enemy warm-up) and the procedural PBR maps are made in workers (`core/pbr.ts` recipes, `PRELOAD` list, `core/pbr.worker.ts`; a map missing from `PRELOAD` is still made on the main thread on first use, just slower), as are the hands' sculpts (`preloadHands` in `entities/models/hands.ts`). Measure with a `longtask` PerformanceObserver: nothing much over ~0.5s.
- **Settings switch live:** a quality preset changes only what needs no shader change (the pixel ratio, MSAA, the shadow map's size, which parts cast shadows, a uniform's steps). Keep new settings in that category, or they cause compile hitches when switched (`src/core/AGENTS.md`).
- **What follows the world is drawn in WebGL, not on the page** (`src/ui/overlay/AGENTS.md`): a page element moved every frame repaints what lies round it, and in Chrome on Windows a repaint that needs a Skia program not yet built holds the game's canvas up for 1 to 4 s. Anything else on the page that must move every frame goes on a layer of its own (`will-change: transform`).
- **Co-op** (`src/net/AGENTS.md`): every game moves and casts its own player, the host's simulates the fight, and each game judges its own hero's hits as its own screen shows them. Anything with gameplay effect goes through the checks in `net/role.ts` (`hitEnemy` needs `by` and deals damage only where `dealsDamage(by)`; `hurtPlayer` only on the local player; props wear down where `hurtsProps(by)`): skill code runs on every game for its visuals. An enemy attack goes through `fx()` in `enemyAI.ts`. Use `G.players` for anything that concerns every player and `G.player` for the local one alone, and bump `PROTOCOL` in `net/session.ts` when the messages change.
- **Asset paths:** Vite `base` is `./`. In `index.html` reference assets root-absolute (`/favicon.svg`) so Vite rewrites them; `check:pages` fails on paths that would break under `/last-stand/pr-preview/pr-N/`.
- Three.js 0.185: use `THREE.Timer` (not `Clock`) and `PCFShadowMap` (not `PCFSoftShadowMap`). Both old forms log deprecation warnings.
- **Dev hooks:** in dev builds, `window.__G` (game state) and `window.__dev.spawnEnemy` are exposed for scripted testing and screenshots (stripped from production). Spawn enemies well away from the player (near the arena edge) or the player dies before the shot.

## Style

- TypeScript strict. Keep data (`src/data`) separate from behaviour, and type new data against `types.ts`.
- Match surrounding code: short header comment per file, sparse comments explaining *why*, compact one-line helpers where the file already uses them.
- **Tools (`tools/`) are written to be read**, held to a higher bar than the game, as a harness is how the game's quality is judged (`tools/AGENTS.md`).
- Styles are SCSS in `src/ui/styles/`, on its theme and mixins (`src/ui/styles/AGENTS.md`). Honour `prefers-reduced-motion` for decorative animation.
