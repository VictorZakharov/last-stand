# `src/ui`

- `?keyboardLock=0` is a diagnostic comparison: keep HTML fullscreen but skip the Escape keyboard lock. Default behavior stays unchanged; in the comparison the browser's Escape exits fullscreen and opens pause. Manual input rows and report metadata distinguish HTML fullscreen and keyboard-lock state from `display-mode: fullscreen`, which also matches browser fullscreen and must not be treated as proof of an installed app.

- The Performance tab's recording controls (`recordingTab.ts`) start a bounded capture and stop/prepare it without sending. Review shows compressed size, Send recording and Discard; hide the inactive Start button then so the review controls stay on one row on a phone. A failed upload retains its exact bytes for retry. Capture/review suppress automatic reports without changing the saved preference. Use a distinct `.recording-note`: reusing `.profile-note` would make the existing profiler write to the recording status instead. `lab recorder` checks the real controls and service round-trip; `ui --states pausePerformance` shows the recording review and full profiler results together.

The page's UI over the game.

- Google sign-in/link uses `cloudSaves.ts`'s waiting dialog with Show Google window, Cancel and Continue in this tab. Only these waiting controls may operate while `act` is busy; closing the dialog aborts the pending attempt. Request foreground synchronously when opening, again when navigating to Google, and on Show Google window; foreground is the browser/OS's decision. Complete through the same save-choice/link/move/error dialogs as the redirect flow, updating the running game in place.
- `fullScreenTrip.ts` preserves the game's HTML fullscreen around Google sign-in/link: suspend automatic entry, await the marked programmatic exit before opening the popup, and restore on success, cancellation, native close or error. A refused restore retries on focus or the next mouse/touch/key gesture; Escape or a manual fullscreen control cancels that retry. A windowed start stays windowed. Do not restore just before a same-tab redirect or while switching to that fallback. `leaveFullScreen()` returns whether the exit succeeded and marks it so `keepEsc` cannot interpret the exit as a pause key. Browser-owned F11 fullscreen cannot be exited through this API.

The rules across the game are the [root AGENTS.md](../../AGENTS.md); each directory under this one has an AGENTS.md of its own.

- **The lobby and menus:** `menus.ts` (the sanctuary with equipment and stash, the summary, pause and help), `loadoutEditor.ts`, `attributes.ts`, `stashFilter.ts`, `tooltip.ts`, `skillDamage.ts` (a skill tooltip's damage), `itemIcons.ts` (an SVG icon per item base), `saves.ts` (the save slots screen), `heroSelect.ts` (the hero selection screen over the hall of heroes), `coop.ts` (the room dialog, the partners' frames, the downed and the revive), `scoreboard.ts`.
- **The run:** `hud.ts` (bars, hotbar, score, target frame, minimap, spoils, the choice after a wave), `floaters.ts` (damage numbers and labels over the world, drawn by `overlay/`), `damageMeter.ts` (the dummies' readout), `touch.ts` (the touch controls), `ping.ts` (co-op pings: Left Shift held and let go, a long press on the minimap).
- **The performance report prompt** (`#perf-ask`) is `src/perf/consent.ts`'s, its styles `styles/_perfAsk.scss`: never in a fight, under the choice after a wave while that shows, its buttons a finger's height on touch (`lab ui --states perfAsk,perfAskBreak,perfAskTouch`).
- **Around it:** `scale.ts` (the UI scaled as a share of the screen), `focus.ts` (a clicked control gives its focus back), `loading.ts` and `logoWind.ts` (the loading screen and its exit), `pwa.ts` (the install link, and a new deploy reloaded onto by itself before the player plays, else offered), `perfHud.ts`, `netHud.ts` and `battleLog.ts` (the overlays down the left, each switched in the pause menu, the performance overlay in three sizes), `clipboard.ts` (their reports copied), `skillArt.ts` (the skill icons), `altCursor.ts` (the cursor drawn over mouse look while Alt is held).

The PWA's worker and caches are `scripts/AGENTS.md`; the skill icons' pictures `skillArt/AGENTS.md`; the world's overlays `overlay/AGENTS.md`; the stylesheets `styles/AGENTS.md`.

## Gotchas

- The automatic fullscreen gesture listener is installed by a tiny inline script (`bootFullScreen.ts`, injected in the head by `vite.config.ts`), before the game's module graph loads. Requests happen synchronously in the activating event, not deferred to boot. `autoFullScreen.ts` takes over the pending/successful request and its prompt/Escape handling. Preserve the opt-out, already-fullscreen display mode, automation and per-visit exclusions in both paths. Standalone PWA windows may enter HTML fullscreen. Permanent boot tests run with no game or controls present.

- Escape opens pause/settings over the hero selection screen, including a first visit before choosing anyone. Selection keys do nothing while pause is open; closing it preserves the focused hero and the hidden lobby hero's idle state. Back alone leaves the selection screen without choosing (and is absent on a first visit). `lab heropick --boot low` checks the first-visit path.

- The Alt cursor forwards label activation as well as the first click: a label's browser-generated checkbox click must not be swallowed by the cursor's capture listener. While captured, selects use `altForms.ts`'s in-page option list below the cursor (z 149 / 150), avoiding native popups stealing capture or covering the cursor. Normal unlocked selects stay native. Ranges map pointer position to min/max/step, emit input while clicking/dragging and change on commit; release, Alt-up and blur end the drag. Cursor movement uses pointermove so cancelling the press's compatibility mouse events cannot stop a drag. `alt-hover` mirrors the virtual cursor's hover chain for CSS effects, including after a hovered popup is removed. **Its layer is over every other of the page's** (`#alt-cursor` in `styles/_base.scss`, z-index 150; the loading screen and a phone's turn-me cover alone are over it): at 60 it was drawn under the beta's notice and the full screen prompt (101), whose buttons couldn't be aimed at (from play: "mouse appears under it, need to be on top, otherwise cannot click"). A new layer's z-index stays under it: `lab cursor` lists any that wouldn't, shown or not.

- `observePerfHud` lets the Dev panel collect the performance HUD's own timing samples without showing or changing the overlay. `perfHudStats` reads the same window used by the full pane. Closing the panel stops its subscription; an enabled overlay keeps collecting normally.

- Collapsed side panels use `.fold-tabs` stacks, which stay visible while panel content is hidden. Equipment and Attributes entry tabs reopen their own right-panel page. The dev module adds Hero/Dev entry tabs to the left stack. One-panel phone/tablet layouts hide the stacks and keep the existing rail (`lab dev --cold` checks the entries and the five viewport layouts).

- **The UI must fit any screen size, desktop and mobile.** Anything that overflows or overlaps at some viewport size is a bug.
  - Scale: `--ui` for the lobby and modals, `--hud` for the in-run HUD, `--touch` for the touch controls (all set in `src/ui/scale.ts`, which `uiScales` exports for code).
  - **The UI is a share of the screen, whatever the OS's scaling**: a 4K screen shows it the same at 100% as at 300% (the fit has no ceiling: capped at 1.35, the UI at 100% was half its size at 300%).
