# `src/ui/styles`

The stylesheets: SCSS partials imported by `index.scss`. The loading screen's styles stay inline in `index.html`, to paint before the bundle.

The rules across the game are the [root AGENTS.md](../../../AGENTS.md).

## Gotchas

- Styles are SCSS in `src/ui/styles/`: one partial per area (`_hud.scss`, `_lobby.scss`, `_modals.scss`...), imported by `index.scss` in cascade order (later files override earlier ones; a moved rule can change what wins). Use the theme (`_theme.scss`: colours named by role, not by hue, so a theme change stays in that file; surfaces; `ui()` / `hud()` / `touch()` scale helpers) and the mixins (`_mixins.scss`: frame, gem, corner brackets, diamond rule, section heading) instead of copying values: plain colours as `var(--frame)`, translucent ones as `rgba($frame, .35)`. The loading screen's styles stay inline in `index.html`. UI scales via the `--ui` variable. Honour `prefers-reduced-motion` for decorative animation.
- **Cursors are the theme's:** `cursor: $cursor-hand` over what takes a click or a drag, `$cursor` where a control shows none (disabled), never a keyword (`pointer`, `grab`, `default`, `help`, `copy`): those show the system's cursor. Their art is inline in `index.html` (`src/ui/AGENTS.md`); a style set from code uses the property (`var(--cursor-hand)`).
- **A looping animation moves only a layer's `transform` or `opacity`**, which the compositor runs without painting anything again. A loop of anything else (a `box-shadow`, a gradient turned by a custom property, a `background-position`) paints its element every frame, whatever layer it's on (a `filter` is composited in Chrome alone): the stash's slot glow did so on every lit item, and with a full stash lit the lobby fell from 145 frames a second to 44 (#267). Draw the effect once and move it: a brighter shadow faded in over the steady one, a conic gradient rotated within a masked ring, a band slid across under `overflow: hidden` (`_items.scss` `.slot-glow`). Check with `npm run lab -- ui --states glow` (every loop a lit item runs), and in the real browser with `npm run stalls -- --scenario hover --stash 40`.
- **Loop the few things in focus, never every item of a kind.** A composited loop still costs every frame: its layer is styled again each frame the page has one (the tooltip following the mouse gives it one a move), layerized, and drawn again by the compositor. 30 lit stash items' 90 loops took the main thread 4 ms a frame and the compositor's draw 3.7 ms, and moving between items halved the frames (72 a second, the owner saw 34) though no loop painted anything; the loops now run on the hovered item and the equipment slots alone, the other items lit steady (`_items.scss`, checked by `lab ui --states glow`; `npm run stalls -- --scenario sweep --stash 60`).
- **An element whose `opacity`, `filter` or `transform` fades often is a layer all along** (`will-change` on all three): one made a layer for each fade and taken off after is painted again each time, and 60 stash items changing focus at once held a frame up 100 to 250 ms (`.sitem, .eslot`).
- **Don't scale a centred box in or out** (the modals' `pop` is a fade alone): centred, its position falls on a fraction of a pixel, which a transform draws as it is, and as the transform ends the box jumps up to a whole pixel, a visible 1 px shift. Measure with the pause probe: the box a frame before its animation ends against it at rest.
